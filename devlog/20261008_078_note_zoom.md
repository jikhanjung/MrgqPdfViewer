# 078 — 메모 모드 확대 · 이동 (v0.6.1-beta.2)

2026-10-08 · P11 후속 · 사용자 요청: "메모 편집으로 들어갔을 때는 악보 zoom/pan 이 가능하게"

## 무엇
- 메모 모드(도구 줄이 떠 있을 때) **두 손가락 = 집어 확대 · 끌어 이동**. 한 손가락 · 펜은 지금처럼 긋는다
- 최대 4배(`NOTE_ZOOM_MAX`), 1배 이하로 집으면 쪽 맞춤으로 풀린다. 화면에 빈 곳이 생기지 않게 이동을 가둔다
- 메모 모드를 끝내면 쪽 맞춤으로 돌아간다. 넘김 · 휴대폰 조각 이동이 표시 행렬을 새로 놓으면 확대는 그냥 풀린다

## 어떻게
- 표시 행렬 = 쪽 맞춤 행렬(`noteZoomBase`) 뒤에 뷰 좌표의 확대 행렬(`noteZoom`)을 붙인 것. `pdfView.imageMatrix` 에 그대로 놓는다
- 메모 · 마디 박스는 이미 `imageMatrix` 로 화면 ↔ 비트맵을 바꾸므로(`windowToBitmap`, `ScoreNotesView.show`, 마디 오버레이) 따로 고칠 것이 없다. 굵기 · 지우개 크기(`pxPerPt`)도 행렬의 배율을 읽는다
- 확대가 풀렸는지는 훅을 걸지 않고 **마지막에 놓은 행렬(`noteZoomApplied`)과 지금 행렬이 같은지**로 본다 — 행렬을 놓는 곳(쪽 맞춤 · 휴대폰 조각 · 애니메이션)이 여럿이라
- `dispatchTouchEvent` 에서 메모 펜보다 먼저 `handleNotePinch`: 두 번째 손가락(둘 다 손가락)이 닿으면 긋던 획을 버리고(`notePen.cancel`), 넘김 몸짓에는 CANCEL 을 보내 탭 · 끌기로 끝나지 않게 한다. 그 터치가 끝날 때까지 모두 먹는다. 손가락 수가 바뀌면 가운데를 다시 잡아 튀지 않게
- 렌더는 그대로(화면 크기 1×) — 확대하면 비트맵을 키우는 것이라 크게 키우면 흐릿하다. 확대한 부분만 다시 렌더하는 것은 써 보고 필요하면

## 확인
- 단위 테스트 · lint 통과. 실기기(태블릿) 확인 전

## 휴대폰: 쪽 단위 (beta.2 뒤, 사용자 요청 "폰 화면에서 메모할 때 pan/zoom 은 페이지 단위로")
- beta.2 는 휴대폰에서도 지금 **조각**(시스템 1 ~ 2개)을 1배로 보고 그 안에서만 키우고 끌 수 있었다 — 뷰 좌표 확대 행렬을 뷰 사각형에 가뒀기 때문
- 이제 확대 상태를 **절대 표시 행렬**(비트맵 → 뷰)로 들고, 범위를 **쪽 비트맵 사각형**으로 가둔다
  - 휴대폰: 배율 = 쪽이 다 들어가는 크기 ~ 폭 맞춤 × 4. 쪽이 화면보다 작은 축은 가운데, 크면 쪽 밖이 보이지 않게
  - 태블릿: 쪽 맞춤 ~ × 4 그대로, 쪽 맞춤보다 작아지면 확대를 푼다(정수 행렬로 돌아가 선명)
- 메모 모드를 끝내면 휴대폰은 화면 맨 위에 가장 가까운 시스템 조각으로 맞춘다(끌기를 놓을 때 `phoneDragEnd` 와 같은 규칙)
- 로컬 컴파일 · 단위 테스트 통과, 실기기 전
