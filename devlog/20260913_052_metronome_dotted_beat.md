# 052 — 메트로놈 점음표 박: 겹박자를 점4분음표로 세기

작성일: 2026-09-13
선행: [`051`](20260913_051_metronome_time_signature.md)(박자 선택), [`050`](20260913_050_time_signature_and_score_follow.md)(악보 연동)

---

## 0. 요약

v0.2.1 까지 박은 항상 박자표 아래 숫자의 음표였다. 6/8 은 8분음표 6번(강약약중약약)이고 BPM 도 8분음표 기준이라,
점4분음표로 적힌 템포(♩. = 72)는 8분음표 216 으로 바꿔 넣어야 했고 **점4분음표 81 이상은 240 BPM 상한에 막혔다.**

사용자와 정리한 결론: 빠르기에 따라 세는 방식이 다르다 — 느린 6/8 은 8분음표 6박, 빠른 6/8 은 점4분음표 2박, 그 사이는 곡과 취향에 따라.
경계가 곡마다 달라 **자동 전환은 하지 않고 파일마다 고른다.**

| 결정 (사용자 승인) | 내용 |
|---|---|
| 방식 | 겹박자(6/8 · 9/8 · 12/8 …)에서만 보이는 **세는 단위 토글**: `8분음표 6박` / `점4분음표 2박`, 파일별 저장 |
| 전환 | **바꿔도 빠르기는 그대로** — BPM 을 3배로 환산 (8분음표 216 ↔ 점4분음표 72) |
| 안내 | 8분음표로 세는데 BPM 이 180(= 점4분 60)을 넘으면 "점4분음표로 세는 편이 편할 수 있습니다" 표시만, 결정은 사용자 |
| 기본값 | 8분음표 (기존 동작 그대로) |
| 쪼개기 클릭 | 넣지 않음 — 점4분 박을 8분음표로 쪼개 울리면 8분음표 모드(강약약중약약)와 같은 소리라 토글이 그 역할을 한다 |

## 1. 설계

- `TimeSignature.beatsPerBar(dotted)` — 겹박자면 `numerator / 3`, 홑박자는 영향 없음.
  `accentAt(i, dotted)` — 점음표 박이면 첫 박 강 · 나머지 중간 (8분음표로 셀 때 묶음 첫 박과 같은 소리).
  `beatNoteName(dotted)` — "점4분음표"(분모 8), "점8분음표"(16)
- `Beat.dotted`, `BarPosition.dotted`, `MetronomeClock.next(bpm, ts, dotted, barPosition)`, `MetronomeEngine.dottedBeat`
- `ScoreFollower(measures, start, dottedBeat)` — 겹박자 마디는 묶음 수만큼, 홑박자 마디는 분모 음표 박으로 센다.
  예비박도 시작 마디의 박 수(6/8 이면 2박). 자동 넘김은 기존 식 `min(TURN_LEAD_BEATS, 박 수 - 1)` 이라 2박 마디에서는 **1박(점4분) 전**.
  위치와 함께 `dotted` 를 넘겨 오디오 스레드가 연동 시작 때의 박 단위로 강세를 판정한다
- `MIN_BPM` 30 → **20** — 느린 겹박자(8분음표 60)를 점음표로 바꾸면 20 이 되는데, 하한에 걸려 빨라지지 않게.
  반대로 점4분 81 이상을 8분음표로 바꾸면 240 에서 잘린다 (그런 빠르기는 점음표로 세라는 뜻이기도 하다)
- 박 표시: `6/8 · ♩. 180`, 점 2개(두 번째 노랑), 묶음 간격 없음
- 대화상자: 박자 버튼 아래에 "세는 단위 — 바꿔도 빠르기는 그대로입니다" + 두 버튼(✓ 표시) + 빠를 때 노란 안내. 템포 줄은 "점4분음표 = 72 BPM"
- DB **v11**: `user_preferences.metronomeDottedBeat INTEGER` (nullable, null = 분모 음표) — `MIGRATION_10_11`

## 2. 검증

- **단위 161개** (156 + 5): `TimeSignatureTest` +2 (묶음 수·음표 이름, 점음표 강세), `MetronomeClockTest` +2
  (점4분 72 = 박당 36750 프레임에 강·중, 점4분 20 이 하한에 걸리지 않음), `ScoreFollowerTest` +1 (6/8 두 박 · 3/4 세 박 섞인 곡)
- **계측 49개** (에뮬레이터 `Television_1080p_2`, API 30 Google TV): `v10_에서_v11_은_점음표_박_컬럼을_더하고_박자_설정을_보존한다` 추가, DAO 저장 테스트에 점음표 포함
- **에뮬레이터 화면 확인** (임시 계측, 커밋 안 함, 대화상자 버튼은 접근성 노드로 눌렀다):
  - 6/8 · 8분음표 216 저장 → `점4분음표 2박` 누르면 엔진 `bpm=72 dotted=true`, 다시 `8분음표 6박` → `bpm=216`. 닫으면 `bpm=72 beats=6 unit=8 dotted=true` 저장
  - 대화상자: "템포: 점4분음표 = 72 BPM", "박자: 6/8 — 점4분음표 2박, 1박 강 · 2박 중간", `✓ 점4분음표 2박`
  - 일반 메트로놈 점4분 180: `0:S@6615 1:M@21315 0:S@36015 …` — 박 간격 14700 프레임 = 44100×60/180 정확, 강·중 교대. 알약 `6/8 · ♩. 180` 점 2개
  - 악보 연동 점4분 240: 예비박 2박(박 0·1) 뒤 박 2 부터 마디 1, 이후 **2박마다 마디 1 → 2 → … → 7**
- 확인 못 한 것: 빠를 때 안내 문구가 실제로 보이는지 (첫 스크린샷이 대화상자가 그려지기 전에 찍혔다 — #051 에서도 같은 현상). 실기기 소리

## 3. 한계

- 박자가 섞인 곡에서 박 길이는 일정하다고 본다 — 점음표 박으로 세면 6/8 마디의 한 박(점4분)과 3/4 마디의 한 박(4분)이 같은 길이로 흐른다.
  분모가 바뀌는 곡의 박 길이 문제는 #050 부터 있던 것이고, MusicXML 의 템포·박 정보로 푸는 것이 맞다
- 악보 연동 중에 대화상자에서 세는 단위를 바꾸면 소리의 BPM 은 바뀌지만 마디 세기는 시작 때 단위를 유지한다 — 정지 후 다시 시작해야 반영된다
