# 054 — 앱 안에서 업데이트 (GitHub Release)

작성일: 2026-09-26
관련: [`docs/4_Build_CI_Release.md`](../docs/4_Build_CI_Release.md)(릴리스 파이프라인)

---

## 0. 요약

지금은 새 버전을 설치하려면 PC 에서 APK 를 받아 adb 로 넣어야 한다. TV 에는 기본 브라우저도 없다.
**설정 → 앱 정보 → "업데이트 확인"** 으로 GitHub 최신 릴리스를 조회하고, 새 버전이면 release APK 를 받아
검증한 뒤 시스템 설치 화면을 띄운다.

```
업데이트 확인 ─▶ GET api.github.com/repos/jikhanjung/MrgqPdfViewer/releases/latest
             ─▶ 태그 vX.Y.Z  >  BuildConfig.VERSION_NAME ?
                  아니오 → "최신 버전입니다"
                  예    → 대화상자: 새 버전 · 크기 · 변경 내용 (CHANGELOG 섹션 = 릴리스 본문)
                           [다운로드 및 설치] ─▶ *-release.apk 다운로드 (진행률, 취소 가능)
                                              ─▶ SHA-256 검증 (에셋 digest)
                                              ─▶ 설치 허용 확인 ("출처를 알 수 없는 앱")
                                              ─▶ 시스템 설치 화면 (사용자가 [업데이트])
```

앱이 **조용히** 설치할 수는 없다(일반 앱의 한계). 사용자가 시스템 설치 화면에서 한 번 눌러야 한다.

## 1. 결정 사항

### 1.1 확인 시점 — 수동만
앱 시작 시 자동 확인은 하지 않는다. 합주 현장에서 네트워크 요청·팝업이 끼어드는 것은 피한다.
필요해지면 "시작 시 확인" 토글을 나중에 추가한다.

### 1.2 조회 — `releases/latest`
- 저장소가 공개라 인증이 필요 없다 (비인증 한도 60회/시간/IP — 수동 확인에는 충분).
- `releases/latest` 는 **draft 와 pre-release(`-rc` 등)를 제외**한다. 릴리스 워크플로우가 `-alpha/-beta/-rc` 를
  pre-release 로 표시하므로 별도 필터가 필요 없다.
- 응답은 Gson `JsonParser` 로 읽는다 (이미 의존성에 있고 JVM 단위 테스트에서도 동작. `org.json` 은 단위 테스트에서 스텁이라 안 된다).

### 1.3 에셋 선택 — `-release.apk` 만
릴리스에는 `-debug.apk` 도 올라간다. **debug APK 는 서명이 달라** 설치된 release 앱 위에 설치하면
`INSTALL_FAILED_UPDATE_INCOMPATIBLE` 로 실패한다. 이름이 `-release.apk` 로 끝나는 에셋만 고른다.

CI 는 `RELEASE_KEYSTORE_*` secrets(2026-09-05 등록)로 서명하므로 release APK 끼리는 같은 키 → 데이터 유지 업데이트.
반대로 **지금 debug 빌드를 쓰는 기기**(Android Studio 설치)는 release APK 로 업데이트할 수 없다 — 대화상자에서 경고한다.

### 1.4 버전 비교
`vX.Y.Z[-suffix]` → 숫자 세 개. 모자란 자리는 0. 접미사가 있으면 같은 숫자의 정식보다 낮게 본다(`0.3.0-rc1 < 0.3.0`).
`releases/latest` 가 pre-release 를 주지 않으므로 접미사 비교는 방어용이다. 태그를 해석할 수 없으면 "알 수 없음"으로 오류 처리.
릴리스 워크플로우가 **태그 == versionName** 을 검증하므로 태그로 비교해도 된다.

### 1.5 저장 위치 — `cacheDir/updates/`
- 앱 전용, 권한 불필요, 사용자에게 보이지 않음. 설치할 파일이 6MB 정도라 캐시로 충분하다.
- 받는 중에는 `*.part` 로 쓰고 검증을 통과하면 이름을 바꾼다 — 끊긴 파일을 설치하는 일이 없다.
- 확인을 시작할 때 폴더를 비운다 (지난 APK 정리). 설치 후 앱이 교체되면 다음 확인 때 지워진다.

### 1.6 무결성 — SHA-256
GitHub 는 릴리스 에셋마다 `digest: "sha256:<hex>"` 를 준다(2025 도입). 받은 파일의 해시와 비교한다.
digest 가 없으면(옛 릴리스·API 변경) 같은 릴리스의 `SHA256SUMS.txt` 에서 찾는다. 둘 다 없으면 **설치하지 않는다**.

> TLS 로 받으므로 변조보다는 **잘림·손상**을 막는 의미가 크다. 최종 신뢰는 Android 의 서명 검증(같은 키가 아니면 업데이트 거부)이 담당한다.

### 1.7 설치 — `ACTION_VIEW` + `FileProvider`
- 매니페스트: `REQUEST_INSTALL_PACKAGES` 권한, `FileProvider`(`${applicationId}.fileprovider`, `cache-path updates/`).
- `file://` 는 API 24+ 에서 `FileUriExposedException` → `content://` URI 에 `FLAG_GRANT_READ_URI_PERMISSION`.
- `PackageInstaller` 세션 API 는 결과 콜백을 받을 수 있지만, 자기 자신을 업데이트하면 앱이 교체돼 콜백을 받을 주체가 사라진다.
  얻는 게 적어 단순한 `ACTION_VIEW` 를 쓴다 (targetSdk 30, 지원 기기 Android 14 에서 동작).
- **설치 허용**: `packageManager.canRequestPackageInstalls()` 가 false 면 설명 대화상자 → `ACTION_MANAGE_UNKNOWN_APP_SOURCES`(이 앱).
  설정 화면에서 돌아오면(`onResume`) 허용됐는지 다시 보고 설치를 이어 간다.
- TV 펌웨어가 설정 화면을 막아 두었으면(`ActivityNotFoundException`) 수동 경로(설정 → 앱 → 보안 및 제한사항)를 안내한다.

### 1.8 네트워크 — `HttpURLConnection`
요청 두 개(JSON, 파일)뿐이라 OkHttp 없이 `HttpURLConnection` 을 쓴다. GitHub 다운로드 URL 은
`objects.githubusercontent.com` 으로 https→https 리다이렉트되고 `HttpURLConnection` 이 따라간다.
타임아웃: 연결 10초, 읽기 30초. `User-Agent`·`Accept: application/vnd.github+json` 헤더.

## 2. 구조

`update/` 패키지:

| 파일 | 역할 | 테스트 |
|---|---|---|
| `AppVersion.kt` | 태그/versionName 해석·비교 | 단위 |
| `ReleaseInfo.kt` | 릴리스 JSON → `ReleaseInfo`(버전·APK 에셋·digest·본문), `SHA256SUMS.txt` 해석, 본문 표시용 정리 | 단위 |
| `UpdateClient.kt` | 조회·다운로드·해시 (IO, suspend) | — |
| `UpdateController.kt` | 설정 화면의 대화상자 흐름 · 설치 허용 · 설치 인텐트 | FileProvider 경로는 계측 |

`SettingsActivity` 는 "앱 정보" 패널에 항목 하나를 넣고 `UpdateController` 를 부르기만 한다.

## 3. 사용자에게 보이는 것

- 앱 정보 → **🔄 업데이트 확인** (부제목: `GitHub 에서 새 버전 찾기`)
- 확인 중 / 다운로드 진행률(MB, %) 대화상자 — 뒤로 누르면 취소
- 새 버전 대화상자: `v0.2.2 → v0.2.3`, 크기, 릴리스 본문(마크다운 기호를 걷어낸 텍스트)
- 실패 메시지는 원인을 구분: 네트워크 · 릴리스에 APK 없음 · 해시 불일치 · 설치 허용 거부

## 4. 한계 · 확인할 것

- **실기기 확인 필요**: Google TV Streamer · Z18TV Pro 에서 "출처를 알 수 없는 앱" 설정 화면이 열리는지, 설치 화면이 뜨는지.
  (메모: Z18TV Pro 는 adb 설치에도 TV 경고가 떠서 사용자 조작이 필요했다)
- 에뮬레이터에서는 debug 빌드라 **실제 업데이트는 서명 불일치로 실패**하는 게 정상이다. 흐름(조회·다운로드·검증·설치 화면 진입)까지만 확인 가능.
- 비인증 API 한도(60/시간)를 넘으면 403 — "잠시 후 다시" 로 안내.

## 5. 구현 · 검증 (2026-09-26)

구현은 §2 구조 그대로. 매니페스트에 `REQUEST_INSTALL_PACKAGES` · `FileProvider`, `res/xml/file_paths.xml`,
설정 → 앱 정보에 🔄 업데이트 확인 (`SettingsActivity` 는 `UpdateController` 생성 · `onResume` · `dispose` 만).

테스트:
- 단위 `AppVersionTest`(5) · `ReleaseInfoTest`(8) — 실제 v0.2.2 응답 모양(debug APK 가 먼저 나오는 순서, 대문자 digest, `digest: null`)
- 계측 `UpdateFileProviderTest` — `updatesDir` 의 파일이 `content://…fileprovider` URI 로 읽히는지 (authority · `file_paths.xml` 어긋남은 실행 중에만 드러난다)

WSL 에는 Linux용 SDK 가 없어 Gradle 을 못 돌린다. 대신 Gradle 캐시의 Kotlin 1.9.22 컴파일러로 직접:
- `update/` 전체를 android-34 `android.jar` + AndroidX(appcompat · core · activity · lifecycle) 에 대고 컴파일 — 오류 없음
- 단위 테스트 13개를 JUnit 스텁으로 실행 — 전부 통과
- **`UpdateClient` 를 실제 GitHub 에 붙여서** (JVM):
  - `releases/latest` → `v0.2.2`, `-release.apk`, digest `631f3070…`
  - 다운로드 5,990,786 바이트, 진행 콜백 23회, `.part` → 최종 이름, `sha256sum` 과 일치
  - digest 를 틀리게 주면 "체크섬 불일치" 로 실패하고 폴더에 아무것도 남지 않음
  - digest 가 없으면 `SHA256SUMS.txt` 로 검증해 성공
  - 없는 저장소 → 404 → "공개된 릴리스가 없습니다"

남은 확인: Gradle 빌드 · Lint · 계측(CI), **실기기에서 설치 허용 화면 → 시스템 설치 화면 → 업데이트 후 데이터 유지**.
실기기 확인은 이 기능이 들어간 버전(v0.2.3)이 설치된 상태에서 **그다음 릴리스**가 있어야 완결된다 — 첫 릴리스에서는
"최신 버전입니다" 와 흐름 진입까지만 볼 수 있다.

부수 발견: 대화상자에 보이는 릴리스 본문은 태그 시점 CHANGELOG 그대로라, v0.2.2 본문의 "실기기 확인 전" 문구가
(이후 실기기 확인했음에도) 사용자에게 보인다. 릴리스 본문은 GitHub 에서 직접 고쳐야 한다.

## 6. 실기기 확인 — Z18TV Pro (2026-09-26) ✅

Windows 쪽 Gradle(`gradlew.bat`, Android Studio JBR)로 `assembleRelease testDebugUnitTest lintDebug` 모두 통과한 뒤,
**versionName 만 `0.2.1-updatetest` 로 낮춘 release 빌드**(versionCode 17 그대로, 정식 키 서명)를 `adb install -r` 로 넣어
GitHub 의 v0.2.2 를 "새 버전"으로 보게 했다. 사용자가 리모컨으로 진행, `ActivityTaskManager` 로그로 확인:

| 시각 | 단계 |
|---|---|
| 18:15:14 | 업데이트 확인 → 다운로드 → 설치 허용 필요 → `ExternalSourcesActivity`(TV 설정) |
| 18:15:24 | 허용 후 돌아오자 `onResume` 에서 이어서 `InstallStart` (`content://com.mrgq.pdfviewer.fileprovider/…`) |
| 18:15:28–41 | `PackageInstallerActivity` → `InstallInstalling` → 앱 교체(app died) → `InstallSuccess` |
| 18:15:49 | 다시 실행, 설정까지 정상 |

- 결과 `versionName=0.2.2`, **`firstInstallTime` 2025-08-02 그대로 = 업데이트(데이터 유지)**
- `REQUEST_INSTALL_PACKAGES: allow` 로 남는다 → 다음부터는 허용 단계 없이 바로 설치 화면
- 첫 `adb install` 때 기기가 `offline` 으로 떨어졌다 → `adb kill-server` 후 재연결로 해결

남은 것: Google TV Streamer 확인. 지금 TV 에는 공식 v0.2.2(이 기능 없음)가 설치돼 있으므로, 이 기능이 든 첫 릴리스는 adb 로 한 번 넣어야 한다.
