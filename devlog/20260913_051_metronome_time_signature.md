## 0. 요약

"지금은 무조건 4분의 x 박자로 하게 되어있는데, 몰다우 같은 경우 8분의 6박자라서. 그것도 선택할 수 있게 해줘." — 사용자 요청.
v0.2.0 의 대화상자는 "마디당 N박" 슬라이더뿐이라 일반 메트로놈은 사실상 x/4 였고, 6/8 을 고를 방법이 없었다
(악보 연동 중에는 이미 악보 박자표를 따랐다, #050).

| 결정 (사용자) | 내용 |
|---|---|
| 고르는 방식 | **흔한 박자는 미리 보여 주고 직접 입력도** — "4/4 3/4 6/8 등은 미리 보여줘. 통계 좀 찾아보고 어느 게 많은지" |
| 악보 박자표 | 대화상자를 **악보에서 읽은 박자표로 채우고 바꿀 수 있게** |
| 6/8 강세 | **1박 강 + 4박 중간** |

## 1. 흔한 박자 순서 — 통계를 찾아봤다

곡 수 기준의 믿을 만한 코퍼스 통계는 **찾지 못했다.**

- MusicScore 데이터셋 논문(arXiv 2406.11462): 양식·악기·조성 통계는 있지만 박자표 분포는 없다
- MidiCaps(Lakh MIDI 기반, arXiv 2406.02255): 박자표 분포 그림이 있으나 로그 척도 그림뿐이라 수치를 뽑지 못했다
- 이베리아 오페라 세리아 코퍼스(arXiv 2509.23771): C(4/4)가 곡의 34% 이하, 3박 계열이 25% 이상 — 특정 레퍼토리라 일반화 불가
- 음악 이론 자료(Pianote "7 Common Time Signatures" 등)는 공통으로 **4/4 가 압도적, 그다음 3/4 · 2/4 · 6/8**,
  홀수 박자 중에는 5/4 가 가장 흔하다고 한다

그래서 순서는 측정값이 아니라 이 공통 순서를 따랐다:
**4/4 · 3/4 · 2/4 · 6/8 · 2/2 · 12/8 · 3/8 · 9/8 · 5/4** (`TimeSignature.COMMON`).
나중에 이 사용자의 악보(`score_measures` 의 박자표) 빈도로 정렬하는 편이 더 정확하다 — 악보가 쌓이면 고려.

## 2. 설계

### `TimeSignature` (metronome/TimeSignature.kt)

- 분자/분모. **박 = 분모 음표, BPM 도 그 음표 기준** (#050 악보 연동과 같은 뜻을 일반 메트로놈에도)
- `isCompound` — 분자가 6 이상의 3의 배수(6·9·12). `accentAt(i)` — 0 은 `STRONG`, 겹박자에서 3의 배수 자리는 `MEDIUM`, 나머지 `WEAK`.
  12/8 은 4·7·10박이 중간 세기. 홑박자(4/4 등)는 지금처럼 첫 박만 강조
- `coerced()` — 분자 1~12, 분모는 2·4·8·16 중 가장 가까운 값 (악보에서 1·32 를 읽은 경우 대비)

### 강세는 박을 놓는 순간 그 마디의 박자로

`Beat` 가 `beatsPerBar` 대신 `timeSignature` 를 들고 `accent` 를 계산한다. 악보 연동의 `barPosition` 은
`(Long) -> Int` 에서 `(Long) -> BarPosition(indexInBar, timeSignature)` 로 바꿨다.

이유: 중간 세기는 **분모까지** 알아야 정해진다. 엔진의 `timeSignature` 필드는 UI 틱이 *들리는* 박을 보고 갱신하는데,
오디오 스레드는 버퍼만큼 앞서 박을 놓는다. 필드에 기대면 3/4 → 6/8 로 바뀌는 마디의 첫 박들을 이전 박자로 판정할 수 있다.
위치와 박자를 함께 돌려주면 오디오 스레드가 스스로 맞게 판정한다 (`ScoreFollower.barPositionAt`, 불변 객체라 스레드 안전).

### 소리와 표시

- `ClickSynth` 에 중간 세기: **F6(1397Hz), 음량 0.75** — 강박 A6/0.9 와 약박 D6/0.6 사이
- 박 표시 알약: `6/8 · ♪ 180` (4분 ♩, 8분 ♪, 16분 ♬; 2분음표 기호 U+1D15E 는 TV 기본 글꼴에 없을 수 있어 숫자만),
  중간 세기 점은 노랑, 겹박자는 3박 묶음 사이를 벌린다. 박자는 **들리는 박의 것**을 그린다 — 바꾼 박자가 소리와 같은 박에서 보인다

### 대화상자

템포 → 박자 설명("박자: 6/8 — 8분음표 6박, 1박 강 · 4박 중간") → 흔한 박자 버튼 두 줄 → 직접 고르기(분자 슬라이더 + `/2 /4 /8 /16` 버튼)
→ 클릭음·음량. 선택된 버튼은 `✓`. 리모컨 입력을 생각해 텍스트 입력 대신 슬라이더·버튼으로 "직접 입력"을 했다.

처음 채우는 값:

| 상황 | 박자 |
|---|---|
| 실행 중 | 지금 박자 |
| 이 파일에서 박자를 고른 적 있음 (`metronomeBeatUnit` 있음) | 저장값 |
| 고른 적 없음 + 악보 박자표를 읽음 | **악보의 첫 박자표** (분석 전이면 이때 분석 — 시작하면 어차피 필요, 결과는 캐시) |
| 고른 적 없음 + 박자표 없음 | 저장된 박 수(v0.2.0)/4, 없으면 4/4 |

v0.2.0 에서 대화상자를 닫기만 해도 박 수가 저장됐으므로, 분모가 없는 행은 "고른 적 없음"으로 본다 — 그래야 이미 열어 본 몰다우도 6/8 로 채워진다.

### DB v10

`user_preferences.metronomeBeatUnit INTEGER` (nullable) 추가 — `MIGRATION_9_10`. 기존 템포·박 수는 그대로 둔다.

### 악보 연동은 그대로 악보를 따른다

연동 중 마디 길이와 강세는 각 마디의 박자표(분자·분모)를 따르고 대화상자의 박자는 쓰지 않는다 (#050 결정 유지).
대화상자가 악보 박자표로 채워지므로 보통 둘은 같다.

## 3. 검증

- **단위 156개** (145 + 11): `TimeSignatureTest` 7 (겹박자 판별, 강세, 범위 자르기, 목록), `MetronomeClockTest` +3
  (6/8 강세 순서와 BPM 기준 — 8분음표 180 = 박당 14700 프레임, 마디 위치의 박자로 중간 세기, 중간 클릭음이 높이·크기 모두 사이),
  `ScoreFollowerTest` +1 (3/4 → 6/8 마디에서 위치와 박자를 함께, 빈 마디는 분모까지 이어받음)
- **계측 48개** (에뮬레이터 `Television_1080p_2`, API 30 Google TV): `v9_에서_v10_은_박_단위_컬럼을_더하고_메트로놈_설정을_보존한다` 추가,
  DAO 저장 테스트에 분모 포함
- **에뮬레이터 화면 확인** (임시 계측, 커밋 안 함): 박자를 고른 적 없는 Moldau 에서 대화상자를 열면
  "템포: 8분음표 = 120 BPM", "박자: 6/8 — 8분음표 6박, 1박 강 · 4박 중간", `✓ 6/8`·`✓ /8` 로 채워짐 → 닫으면 `beats=6 unit=8` 저장.
  일반 메트로놈 12/8·240 BPM 의 박 기록 `0:S 1:W 2:W 3:M 4:W 5:W 6:M 7:W 8:W 9:M 10:W 11:W 0:S …`, 알약 `12/8 · ♪ 240` 에 4번째 점 노랑과 묶음 간격
- 계측 전에 Z18TV Pro 를 adb 에서 끊었다 — 연결된 채로 `connectedDebugAndroidTest` 를 돌리면 release 서명 앱 위에 debug 를 설치하려다 데이터를 잃는다.
  `Television_1080p`(API 29)는 minSdk 30 미만이라 건너뛰어진다

**확인 못 한 것**: 실기기에서 중간 세기 클릭음이 구분되게 들리는지(에뮬레이터는 무음 모드), 리모컨으로 박자 버튼 사이를 오가는 포커스 이동.

## 4. 한계와 다음

- **점4분음표 박이 없다.** 박은 항상 분모 음표라 빠른 6/8(점4분 = 90 이상)은 8분음표 270 이상이 되어 `MAX_BPM` 240 에 막힌다.
  몰다우(점4분 60~72 → 8분 180~216)는 범위 안. 필요해지면 "박 단위: 8분 / 점4분" 선택이나 상한 상향
- 박자가 바뀌는 곡은 대화상자를 첫 박자표로만 채운다
- 흔한 박자 순서는 측정값이 아니다 (§1)
