## 0. 요약

- **무엇**: **자기 총보**를 열고 "파트: 진호" 를 고르면, 매 시스템에서 그 파트의 보표만 잘라 이어 붙인 화면으로 본다. 새 파일을 만들지 않는다 — **보기 방식**이다.
  **혼자 연습할 때가 기본**이고, 합주 모드의 연주자도 같은 화면을 쓴다
- **반주 연습** (§2.7): 그 곡의 MusicXML 이 있으면 메트로놈을 틀 때 **다른 파트들의 연주를 들려준다** — 내 파트만 빼고. 합주에 맞춰 보는 연습.
  빠르기는 메트로놈(느리게 연습 · 구간별 빠르기)을 따르고, 소리는 메트로놈 클릭과 같은 AudioTrack 에 섞어 **샘플 단위로 박에 맞는다**
- **합주에서도 맞는 이유**: 원본이 지휘자와 **같은 총보 파일**이라
  - 파일 찾기(`file_change` 의 SHA-256)가 그대로 맞는다
  - 마디 번호가 총보 분석(`score_measures`) 그대로라 지휘자와 같다. 여러 마디 쉼표 · 못갖춘마디 차이가 없다(따로 그린 파트보 PDF 와 다른 점)
  - 필요한 것은 **마디 ↔ 파트 화면 위치 표** 하나. 쪽 넘김(`page_change`) · 시작 마디 · `focus_measure` · 현재 마디 · 스스로 넘김이 이 표로 옮겨진다
- **저작권**: 서버 P01 §2 의 ①②에 해당 — 각자 정당하게 가진 총보를 자기 기기에서 다르게 보는 것. **파트 화면을 기기 사이에 보내는 경로는 만들지 않는다**
- **범위 밖**: 파트보 PDF 내보내기 · 공유, 스캔본(벡터 분석이 안 되는 PDF), MusicXML 을 앱에서 만들기(서버 P01 의 OMR · 악보 프로그램 내보내기가 만든다), 합주 모드에서 반주 재생(실제 연주자가 있다)

## 2. 설계

### 2.1 분석 — 파트 목록과 보표 띠 (DB v15)

- 시스템마다 보표 띠(`staffBands`)를 저장한다. 새 표 `score_staves(pdfFileId, pageIndex, systemIndex, staffIndex, topPt, bottomPt)` — 분석 캐시와 같이 파일 내용이 바뀌면 다시 분석
- **파트 = 보표 순번** (1차). 모든 시스템의 보표 수가 같을 때만 파트 보기를 켠다
  - ⚠️ Sibelius · MuseScore 의 "빈 보표 숨기기"(쉬는 파트를 빼고 조판)면 시스템마다 보표 수가 다르다 → 1차는 **"이 악보는 파트 보기를 지원하지 않습니다"**. 2차에서 보표 이름 · 음자리표로 맞춘다(§4)
  - **보표 하나 = 파트 하나**로 간다(사용자 결정 2026-09-28 — 쓰는 악보가 기타 2 · 3 · 5중주라 보표마다 한 파트). 한 파트가 보표 두 개(피아노 · 하프)인
    악보는 필요해지면 "연속된 보표를 한 파트로 묶기"를 더한다
- **파트 이름**: 첫 시스템 보표 왼쪽 텍스트(악기 · 사람 이름)를 박자표처럼 텍스트 위치로 읽는다(`TimeSignatureDetector` 와 같은 길). 못 읽으면 "보표 1, 2, …"

### 2.2 파트 화면 배치 — `PartLayout` (JVM 단위 테스트 대상)

- 입력: 보표 띠 목록(쪽 · 시스템 · 파트의 띠) · 화면 크기 · 여백 설정. 출력: **가상 쪽** 목록 — 쪽마다 조각(원본 쪽 · 원본 사각형 → 가상 쪽 위치)
- 가상 쪽은 **세로 A4 비율**로 만든다 → 기존 한 쪽 / 두 쪽 모드 · 페이지 넘김 애니메이션 · 효과음을 그대로 쓴다. 가로 화면이면 두 쪽 모드로 두 개가 보인다
- 띠 자르기: 보표 위아래로 **이웃 보표와의 가운데까지**(덧줄 · 셈여림 · 가사를 살리고 옆 파트는 들이지 않는다). 첫 보표면 시스템 위 글자(빠르기 · 리허설 마크)까지 포함할지 옵션 — 아래 파트는 이 글자를 잃는다(§4)
- 조각 사이 간격, 쪽 첫 조각 왼쪽에 **마디 번호를 앱이 직접** 그린다(총보의 마디 번호는 보통 맨 위 보표에만 있다)

### 2.3 렌더

- 조각마다 `PdfRenderer.Page.render` 에 Matrix(scale + translate) 와 clip 을 줘 가상 쪽 비트맵에 바로 그린다 — 중간 비트맵 · 재샘플링 없음. **정수 좌표 · 1×** 원칙(#042) 그대로
- `PageCache` 의 키를 (파일, 파트, 가상 쪽)으로 넓힌다. 한 가상 쪽이 원본 2~3쪽을 여는 경우가 있어 렌더 비용을 재 본다(Z18TV Pro 기준)

### 2.4 마디 ↔ 파트 화면 위치 표

- `PartLayout` 이 마디마다 (가상 쪽, 가상 쪽 안 사각형)을 낸다 — 원본 마디 상자(`score_measures` 의 좌우 x)와 조각의 변환으로 계산
- 이것 하나로 옮긴다:
  - **마디 박스 오버레이 · 현재 마디 노란 표시 · 시작 마디 커서** — 원본 좌표 대신 파트 좌표
  - **스스로 넘김**(`TURN_LEAD_BEATS`) — "이 가상 쪽의 마지막 마디" 기준. 파트 화면은 쪽당 마디가 많아 넘김이 준다
  - `ensureMeasureVisible` — 마디가 있는 가상 쪽으로

### 2.5 합주

프로토콜은 **바꾸지 않는다**. 연주자 쪽 해석만 파트 화면으로:

| 받는 것 | 지금 (총보) | 파트 보기 |
|---|---|---|
| `file_change`(SHA-256) | 같은 파일 열기 | 같다 — 연 뒤 이 파일의 파트 설정으로 |
| `page_change`(총보 쪽 N) | N 쪽으로 | 총보 N 쪽의 **첫 마디**(`score_measures`) → 그 마디가 있는 가상 쪽으로. 두 쪽 모드 지휘자면 N 은 왼쪽 쪽 |
| `metronome_run` 의 `start_measure` · `focus_measure` · 시간표 | 마디 번호 → 총보 위치 | 마디 번호 → 파트 위치 (시간표 · 박은 마디 목록이 같아 그대로) |

- 지휘자가 파트 보기를 써도 같다 — 보내는 쪽 번호는 **총보 기준**으로 바꿔 보낸다(가상 쪽의 첫 마디가 있는 총보 쪽). 그래야 총보를 보는 연주자와 섞여도 맞다
- 분석이 안 된 파일(마디를 모름)은 파트 보기를 켤 수 없으므로 이 경우는 생기지 않는다

### 2.6 화면 · 설정

- PDF 표시 옵션(OK 길게)에 **"파트: 전체 악보 / 진호 / 예진 / …"** — 파일별 저장(`user_preferences` 에 `partStaves` 문자열, 예 `"2"` · `"4-5"`, v15). 전체 악보 = 지금과 같음
- 파트 보기 중에는 위/아래 클리핑은 쓰지 않는다(조각이 이미 잘려 있음). 중앙 여백은 두 쪽 모드에서 그대로
- 쪽 번호 표시는 "파트 3/5 쪽 (총보 7쪽)" 처럼 둘 다

### 2.7 반주 연습 — MusicXML 로 다른 파트 들려주기

**구하는 곳**
- ScoreMate 동기화: 서버 P01 §4 가 판별 분석으로 MusicXML 을 두면(`analyzer="astra-musicxml"` 등) 악보와 함께 받는다 — 서버 요청은 P06 에 추가
- 웹 업로드 · 로컬: 같은 이름의 `.musicxml` / `.mxl` 을 PDF 옆에 둔다 (연결하지 않은 TV)
- 한 파일에 하나. 판이 바뀌면(ScoreMate 새 판) 같이 바뀐다

**맞추기 — 쓰기 전에 검사**
- MusicXML 마디 수 · 박자표 흐름이 이 PDF 분석(`score_measures`)과 같아야 켠다. 다르면 "악보와 MusicXML 의 마디가 맞지 않습니다" 로 끈다(판 불일치 · OMR 오류를 여기서 거른다 — 서버 P01 §3 의 판 검사와 같은 규칙)
- 못갖춘마디(`implicit="yes"`, 마디 0) · 도돌이표는 1차에서 **악보에 적힌 순서 그대로**(악보 연동과 같다, #050 — 반복을 펼치지 않는다)
- **파트 대응**: MusicXML `<part>` 순서 = 총보 보표 순서(위→아래)가 보통이다. 보표 둘짜리 파트(`<staves>2`)는 보표 두 개를 차지. 이름(`part-name`)과 §2.1 의 파트 이름을 같이 보여 주고 틀리면 사용자가 고친다

**재생**
- `MusicXmlScore`(JVM 단위 테스트 대상): 파트별 음표 목록 = (마디, 마디 안 위치(분수 박), 길이, 음높이, 붙임줄 이음). 셈여림은 1차에서 무시(고른 세기)
- 음표 시각 = `ScoreFollower` 의 박 시각으로 옮긴 값 → **메트로놈 빠르기를 그대로 따른다**(느리게 연습하면 반주도 느리게, 구간별 빠르기도). 예비박 동안은 조용히
- 소리 만들기: `MetronomeEngine` 이 청크마다 클릭을 쓰기 전에 반주 신디사이저가 같은 512프레임을 채우고 클릭을 더한다
  - 소리는 **단순 합성**(사인 · 배음 몇 개 + 감쇠, 파트마다 음색을 조금 달리) — 에셋 없음. 합주를 맞춰 보는 데는 음높이 · 박만 들리면 된다
  - Android 내장 Sonivox(MIDI 파일 → MediaPlayer)는 쉽지만 **다른 시계**라 박과 어긋나고 템포 변경 · 일시정지를 못 따른다 → 쓰지 않는다
  - 악기 소리(사운드폰트 SF2 샘플러)는 **나중에 생각한다**(2026-09-28 사용자 결정). 합성기를 인터페이스 하나 뒤에 두어 바꿀 자리만 남긴다
- **내 파트는 빼고**, 파트별 켜기 · 끄기 · 크기(메트로놈 상세). "내 파트도 작게"(음 확인용) 옵션. 클릭은 따로 끌 수 있다(반주만)
- 일시정지 · 이어서 · 마디 골라 다시(#053)는 악보 연동과 같다 — 반주는 그 시간표를 따르므로 따로 할 일이 없다

**합주 모드에서는** 반주를 끈다(실제 연주자가 있다). 연주자는 지금처럼 클릭만 고른다(`ensemble_metronome_sound`)

## 3. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| **1. 분석** | `score_staves` 저장(DB v15), 시스템마다 보표 수 일정 검사, 파트 이름 읽기 | Moldau(5보표) · MuseScore 2보표 악보 단위 테스트 — `data/Moldau0607_layout.json` 과 띠 비교 |
| **2. 배치 · 렌더** | `PartLayout`(JVM) + 가상 쪽 렌더 + 표시 옵션의 파트 선택 | `data/parts/` 의 결과와 눈으로 비교, Z18TV Pro 렌더 시간 |
| **3. 마디 표** | 오버레이 · 악보 연동(시작 마디 · 현재 마디 · 스스로 넘김)을 파트 좌표로 | 메트로놈 악보 연동을 파트 보기에서 끝까지 |
| **4. 합주** | `page_change` · `metronome_run` 을 파트 위치로, 지휘자 파트 보기의 쪽 번호 환산 | 2대: 지휘자 총보 · 연주자 파트 / 반대 |
| **5. MusicXML 받기 · 맞추기** | 로컬 `.musicxml`/`.mxl` 읽기(`MusicXmlScore`), 마디 · 박자표 · 파트 대응 검사. ScoreMate 동기화는 서버가 준비되면 | Moldau: 서버 P01 실험의 Astra MusicXML(1~2쪽) · Sibelius 내보내기 |
| **6. 반주 재생** | `MetronomeEngine` 청크 믹싱 + 단순 합성, 파트별 켜기 · 크기 | 느린 빠르기 · 구간별 빠르기 · 일시정지 이어서에서 박과 음 어긋남 없음(녹음해 확인) |

1~3단계면 혼자 파트보로 메트로놈 연습, 5~6단계를 더하면 반주 연습. 4단계(합주)는 따로 순서를 정한다 — 혼자 연습이 먼저다.

## 4. 열린 질문

1. **빈 보표 숨긴 총보** — 시스템마다 보표 이름(짧은 이름 "Vn. I")으로 맞출지, 음자리표 · 조표 흐름으로 맞출지. 그 시스템에 파트가 없으면 쉼표 줄을 앱이 그릴지 비워 둘지
