# 048 — minSdk 21 → 30: 지원 하한을 실사용 기기에 맞춘다

작성일: 2026-09-13
계기: `3f506dc`(047) 의 Instrumentation 이 **API 21 에서 실패**

---

## 0. 요약

minSdk 를 **21(Android 5.0) → 30(Android 11)** 로 올리고 CI 계측 매트릭스를 **API 30/34** 로 줄였다.

> ⚠️ **정정 (같은 날, #049)**: 아래에서 "Z18TV Pro = Android 11" 로 판단한 것은 **출고 사양**이었다. 실기기에
> adb 로 연결해 보니 **Android 14 (API 34)** 로 업데이트돼 있었다. 실사용 기기 두 대가 모두 Android 14 다.
> 사용자 결정으로 minSdk 는 **30 을 유지**한다 — 두 기기 모두 설치되고, Android 11 기기에도 여지를 남기는 보수적 하한.

| 기기 | OS | 역할 |
|---|---|---|
| Z18TV Pro (제우스랩) | 출고 Google TV Android 11 → **실기기 Android 14** (API 34) | 실사용 |
| Google TV Streamer | Android 14 (API 34) | 현재 주 기기 — CI API 34 |
| (에뮬레이터) | Android 11 (API 30) | 지원 하한 — CI API 30 |

## 1. 계기 — API 21 에서 악보 분석 테스트가 메모리 부족으로 죽었다

```
Starting 42 tests on emulator-5554 - 5.0.2
Finished 35 tests …  Test run failed to complete. Expected 42 tests, received 35.
1) com.mrgq.pdfviewer.ScoreLayoutAnalyzerTest
java.lang.OutOfMemoryError: Failed to allocate a 4108 byte allocation with 4194304 free bytes and 16MB until OOM;
failed due to fragmentation (required continguous free 8192 bytes where largest contiguous free 4096 bytes)
```

- 여유 메모리는 있었지만 **조각나서** 연속 8KB 를 못 얻었다 (Android 5.0 의 비이동 GC)
- 테스트 프로세스가 통째로 죽어 뒤의 7개가 돌지 않았다
- **같은 테스트가 직전 커밋 `f154262` 의 API 21 에서는 40개 전부 통과**했다 — 코드가 망가진 게 아니라
  13쪽 분석이 API 21 의 작은 힙에 걸쳐 있다가 이번에 넘친 것. 한 번 통과·한 번 실패하는 불안정한 게이트였다
- API 30·34 는 통과

## 2. 결정

선택지는 ① 분석 메모리 줄이기 ② 테스트만 조정 ③ API 21 에서 건너뛰기였다. 사용자가 방향을 바꿨다:
**"Z18TV Pro 버전부터 지원한다고 하는 게 낫겠다."**

- 이 앱은 사이드로딩으로 **본인 기기에만** 쓴다. Android 5.0~10 을 지원해서 얻는 사용자가 없다
- 그런데 그 구간을 지원한다는 선언 때문에 CI 가 가장 느리고(x86 5.0 에뮬레이터) 가장 불안정한(작은 힙) 매트릭스를 돌았다
- 043 에서 기록한 "minSdk 21 을 선언만 하고 검증한 적 없다" 문제의 근본 해법이기도 하다 — 쓰지 않는 하한을 검증하는 대신, 쓰는 기기를 하한으로 삼는다

### 기기 OS 확인 (추측으로 두지 않았다)

저장소에는 `targetSdk = 30  // Android TV OS 11` 주석만 있고 기기 OS 가 명시돼 있지 않아 웹에서 확인했다:

- 제조사 판매 페이지 사양: **"Google TV Android 11"**, Amlogic 쿼드코어, **RAM 2GB**, eMMC 8GB
- 국내 리뷰: 설정 화면 버전 표기로 "안드로이드 11 기반", 칩셋 Amlogic S905Y4
- 2세대 Z18TV PRO 는 Android TV 14 라는 정보가 있으나, 2025-07 부터 쓰던 기기는 1세대로 판단
- ⚠️ **틀렸다** — 출고 사양만 보고 실기기를 확인하지 않았다. 실기기는 펌웨어 업데이트로 Android 14 였다 (#049 §5)

## 3. 바꾼 것

| 파일 | 변경 |
|---|---|
| `app/build.gradle.kts` | `minSdk = 30` (사유 주석) |
| `.github/workflows/instrumentation.yml` | 매트릭스에서 API 21 제거, API 30 = minSdk = targetSdk |
| `.github/scripts/release_smoke.sh` | API 21 toolbox 대응 주석을 과거형으로 (동작은 그대로) |
| `SimpleWebSocketConnection.kt` | Base64 주석 보강 (코드 그대로) |
| `CLAUDE.md`, `README.md`, `docs/4`, `CHANGELOG.md` | 현재 상태 기술만 갱신. 과거 기록(043~047, 과거 릴리스 항목)은 당시 사실이라 그대로 |

### 바꾸지 않은 것

- API 21~29 호환 코드(`android.util.Base64`, `ContextCompat.getColor`, 23자 로그 태그 등)는 minSdk 30 에서도 무해해 그대로
- Lint 의 `ObsoleteSdkInt` 경고 4건 — `NetworkUtils.kt` 2곳, `PdfViewerActivity.kt` 1곳의 `SDK_INT` 분기와
  `mipmap-anydpi-v26` 폴더. 경고일 뿐이고 동작에 영향이 없어 이번 변경과 섞지 않았다

## 5. 남은 것 — 메모리 문제는 사라지지 않았다

> ✅ **같은 날 해결 (#049)**: 분석 경로에서 PdfBox 엔진을 빼고 경량 해석기로 바꿔 할당 905MB → 19MB.
> Z18TV Pro 실기기에서 8쪽 556ms.

API 21 매트릭스가 빠지면서 CI 에서는 OOM 이 보이지 않게 됐지만, **Z18TV Pro 는 RAM 2GB** 다. 앱 힙은 넉넉하지
않고, 에뮬레이터에서 13쪽 분석에 8.9초가 걸렸던 것(#046)도 이 기기에서는 더 느릴 수 있다.

- 악보 분석 메모리 줄이기: PdfBox 작업 버퍼를 임시 파일로(`MemoryUsageSetting.setupTempFileOnly`), 페이지별 경로 데이터를 페이지마다 버리기
- **Z18TV Pro 실기기에서** 분석 시간·메모리 측정
- `ObsoleteSdkInt` 정리 (별도 커밋)
