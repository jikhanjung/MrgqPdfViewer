## 0. 왜

서버 0.7.0 부터 TV 는 웹에서 고른 세트리스트의 곡만 받는다(기존 TV 는 "모든 악보"). TV 에서도 세트리스트 단위로 보고, 연주회에서 곡 순서대로 넘길 수 있어야 한다.

## 1. 화면

```
 ☁️ ScoreMate    모든 악보 5    2027 연주회 5         ← 세트리스트 줄 (연결된 TV · 받은 세트리스트가 있을 때만)
                                ━━━━━━━━━━━
                                        [☁️ 동기화] [파일관리]      ← 세트리스트를 고르면 정렬 버튼은 숨김
 1. Clair de Lune 20260717.pdf                    ☁️ 내 악보 · 판 1 • …
 2. SM-000234705_02052026.pdf     📝 (곡 메모) •  ☁️ …
```

- [모든 악보] + 받은 세트리스트. 포커스만 옮겨도 바뀐다(리모컨 키 뒤 500ms 안의 이동만 — 저절로 놓인 포커스는 무시). 많으면 옆으로 넘어간다
- 고른 것을 기억한다(`scoremate_setlist`). 그 세트리스트가 없어지면(웹에서 해제 · 연결 해제) 모든 악보로
- 세트리스트를 고르면 **곡 순서대로 번호**, 곡 메모는 📝. **악보 화면의 이전/다음 파일도 곡 순서** (목록을 그대로 넘긴다)
- 이 TV 에 아직 없는 곡(받는 중 · TV 에서 숨김)은 빼고 왼쪽에 "☁️ ScoreMate · 6곡 중 5곡"
- 줄 다시 그리기는 세트리스트 구성이 바뀔 때만 — 글자 · 선택 표시만 바꿔 포커스를 잃지 않게

## 2. 받기 · 저장

- 동기화(`ScoreMateSync.sync`)가 악보 다음에 `GET /api/v1/sync/setlists/` 를 받아 응답 그대로 prefs(`scoremate` 의 `setlists`)에 저장 — 오프라인에서도 보인다.
  개수가 적어 통째로 바꿔 끼운다. 바뀌었으면 `SyncReport.setlistsChanged`("세트리스트 갱신") → 목록을 다시 그린다
- 세트리스트를 못 받아도 악보 동기화는 된 것 — 저장한 세트리스트를 그대로 쓴다(오류는 알림에만)
- 곡은 서버 악보 id(`score_id`)로 가리키므로 받아 둔 악보(`server_scores`)와 잇는다 — 같은 서버의 같은 계정 데이터라 id 로 충분하다
  (합주의 파일 맞추기가 id 대신 내용 해시인 것과 다르다: 그쪽은 서버 · 계정이 다를 수 있다)
- 연결을 끊으면 토큰 · 커서와 함께 지운다

## 3. 하지 않은 것

- 합주에서 지휘자가 보는 세트리스트를 연주자에게 알리기 — 합주는 지금처럼 파일 단위(내용 해시)
- 세트리스트 설명(`description`) · 앙상블 이름 표시 — 줄이 길어져서. 필요하면 상세에

## 4. 이후 — "모든 악보" 탭 제거 (2026-09-28, v0.2.8 실기기 테스트 중)

- 원칙: **연결된 TV 는 세트리스트를 받아 세트리스트로 본다.** 곡목에 든 악보만 받으므로(서버 0.7.0 기본) [모든 악보] 는 쓸 일이 없다 → 줄은 **[곡목 …] 만**
- 고른 적 없거나 고른 곡목이 없어지면 **첫 세트리스트**. 받은 세트리스트가 없으면 빈 화면("받은 세트리스트가 없습니다" + 웹에서 고르라는 안내)
- 연결된 TV 에서는 정렬 버튼을 항상 숨긴다(곡 순서)
- 웹에서 이 TV 를 "모든 악보"로 둔 경우에도 어느 곡목에도 없는 악보는 보이지 않는다(받기는 함) — 의도한 동작

## 5. 테스트

- `ScoreMateSetlistsTest` 2개: 곡 순서대로 읽기 · 깨진 세트리스트/항목 건너뛰기 · 빈 제목 · 이 TV 파일과 잇기(없음 · 숨김은 경로 없음)
- `ScoreMateSyncTest`: 세트리스트 받아 저장 · 같으면 바뀐 것 아님 · 못 받아도 저장한 것 유지
