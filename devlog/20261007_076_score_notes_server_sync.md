## 2. 한 일
- **곁 파일의 동기화 상태** `"sync": {"revision", "base_ids"}` (`ScoreNotesFile.SyncState`) — 서버와 마지막으로 맞춘 revision 과 그때 있던 메모 id. 이 기기만의 것이라 서버에 올릴 때는 뺀다(서버도 모르는 키는 버림)
  - 뷰어 저장(`saveAsync`)은 메모만 바꾸고 sync 는 파일에 있던 것 그대로
  - 맞춘 적이 있으면 메모가 비어도 파일을 지우지 않는다 — 빈 문서를 올려야 서버에서도 지워진다
  - 곁 파일 읽기 · 쓰기는 `ScoreNotesFile.lock` 안에서(뷰어 저장 스레드 · 동기화가 겹치지 않게)
- **합치기** `ScoreNotesFile.merge(remote, local, baseIds)` = 서버 ∪ (지금 − base) − (base − 지금). 메모는 불변(고치면 새 id)이라 id 집합만으로 된다. 모르는 type 도 같은 규칙
- **`ScoreNotesSync`**(scoremate/) — 악보 동기화 끝(세트리스트 다음)에 개인 메모(`personal`). 악보마다:
  | 서버 목록 | 내 상태 | 하는 일 |
  |---|---|---|
  | 없음 | 맞춘 적 없음 · 메모 있음 | `base_revision` 0 으로 처음 만들기 |
  | 없음 | 맞춘 적 있음 | 아무것도 안 함 — **목록에서 빠짐 ≠ 삭제**(범위 밖) |
  | 내 revision 과 같음 | 바뀜(id ≠ base) | 올리기 |
  | 내 것과 다름 | — | 받아서 합침 → 서버와 같으면 받기만, 다르면 올리기 |
  - 409: `current` 와 다시 합쳐 그 revision 으로(두 기기가 동시에 처음 만든 경우 포함), `current: null` 이면 0 으로 다시. 3번까지
  - 네트워크 동안 뷰어가 곁 파일을 고쳤으면(id 가 읽은 때와 다름) 쓰지 않는다 — 다음 동기화에
  - 서버가 메모 API 를 모르면(목록 404) 조용히 건너뜀. 실패는 알림의 오류로, 악보 동기화는 그대로
  - `pdf_sha256` 은 그 악보의 서버 판 sha(`server_scores.sha256`)
- `ScoreMateClient`: `fetchNotesList` · `getNotes` · `putNotes`. 알림 "메모 n곡 올림 · 받음"
- 테스트: `ScoreMateSyncTest` +8(가짜 서버에 메모 API — 모르는 서버, 처음 올리기 base 0 · 다시 안 올림, 받기, 양쪽 합치기, **동시 처음 만들기 409 + current**, **409 current null → 0**, 다 지우기 → 빈 문서, 목록에서 빠짐), `ScoreNotesTest` +2(합치기, sync 상태 왕복 · 보낼 때 뺌). 반장 · 사용자가 요구한 두 경로(base 0, 동시 생성 409) 포함

## 3. 범위 밖 · 남은 것
- **지휘자 메모(conductor)** — 받기 · 보이기(개인 메모와 다른 모양) · `conductor_writable` 이면 쓰기 겹 고르기. 곁 파일 `.conductor.notes.json`
- 로컬(웹 업로드) 파일 · 합주 캐시 파일 메모는 올리지 않는다
- 실서버 확인: 태블릿 → 서버 웹 겹쳐 보기, 휴대폰으로 받기 · 고치기 → 태블릿
