## 0. 요약

1. **메트로놈 대화상자 단순화** — 첫 화면은 박자(2/4 · 3/4 · 4/4 · 6/8 버튼) · 속도 · 소리 크기 세 줄. 나머지는 줄마다 "상세…"
2. **구간별 빠르기** — 악보 박자가 바뀌는 마디마다 구간이 생기고, 구간마다 앞 구간에서 빠르기를 이어받는 방법 · 세는 단위를 정한다.
   악보 연동과 **합주 동기화까지** 구간 템포로 돈다
3. 구간 목록 · 구간 설정에 **몇 마디부터 몇 마디까지인지**(마디 수 포함)를 보인다 (사용자 요청)

사용자 결정:
- 박자가 바뀔 때 기본은 **음표 길이 그대로**(분모 음표 유지, 4/4 ♩=96 → 6/8 ♪=192), 사용자가 바꿀 수 있다
- 1단계만: **박자가 바뀌는 곳의 구간 자동 생성 + 구간별 빠르기**. 템포만 바뀌는 곳(Più mosso 등)에 구간을 더하는 건 2단계
- 합주 동기화까지 한 번에

## 1. 대화상자

```
구간 1 / 3 · 1~32마디 (32마디) · 4/4 — 아래 설정은 이 구간
박자: 4/4 — 4분음표 4박 · 악보 박자표          [상세…]
      [2/4] [3/4] [✓ 4/4] [6/8]
속도: 4분음표 = 96 BPM                           [상세…]
소리 크기: 60%                                   [상세…]
다른 구간 — 박자가 바뀌는 곳마다 나뉩니다
  [구간 2 · 33~56마디 (24마디) · 6/8
   음표 길이 그대로 · 8분음표 = 192]
  [구간 3 · 57~80마디 (24마디) · 4/4
   음표 길이 그대로 · 4분음표 = 96]
```

- 상세 버튼은 슬라이더 옆이 아니라 **제목 줄**에 있다 — 슬라이더가 ←→ 를 쓰므로 리모컨으로는 ↑↓ 로만 닿는다
- 박자 상세: 흔한 박자 9개 · 분자 슬라이더 · 분모 버튼 · 세는 단위(겹박자). 속도 상세: ±1 · ±10. 소리 상세: 클릭음 켜기/끄기
- 구간 화면(구간 2부터)은 **첫 화면과 같은 짜임**(실기기에서 본 뒤 사용자 요청): 박자 · 속도 · 소리 크기, 줄마다 "상세…".
  박자는 악보가 정하므로 박자 줄에는 겹박자일 때 세는 단위 버튼만(아니면 "박자는 악보 박자표를 따릅니다"). 속도 슬라이더를 옮기면 "직접 입력".
  속도 상세 = 앞 구간 요약 · 이어받기 3가지(선택지마다 결과 템포) · ±1 · ±10. 소리 크기는 첫 화면과 같은 값(전역)
- 연주 중 마디 표시 테두리를 가늘고 반투명하게: 6px → 3px, 주황 알파 0x99 (번호표는 불투명). 시작 마디 커서(파랑)는 그대로 (사용자 요청)
- 구간은 악보가 있어야 알 수 있어, 대화상자를 열 때 **분석 전인 파일은 분석한다**(전에는 박자를 고른 적 없는 파일만). 결과는 DB 캐시

## 2. 모델 (`metronome/TempoSections.kt`)

| | |
|---|---|
| `SectionSpan` | 악보 박자로 나눈 구간 — 시작 · 끝 마디, 마디 수, 박자. `spans(measures)` 는 `ScoreFollower` 와 같은 규칙(박자를 아는 첫 마디부터, 빈 박자표는 앞 마디를 잇는다) |
| `TempoSectionSetting` | 둘째 구간부터 사용자가 정한 것: 시작 마디 · 이어받기(`NOTE` · `BEAT` · `SET`) · bpm(`SET` 일 때) · 점음표 박 |
| `TempoSection` | 설정을 입혀 푼 것. bpm 은 **소수**(♩=97 → ♩.=64.67) — 박 간격 계산용, 화면에는 반올림 |
| `forFollowing` | 악보 연동용. **구간이 하나뿐인 곡은 빈 목록** → 곡 전체를 엔진 템포로 (v0.2.4 와 똑같이 — 연주 중 템포 조절도 그대로) |

- 첫 구간 = 파일의 기존 메트로놈 설정(템포 · 점음표 박). 저장은 둘째 구간부터만 → 기존 파일은 바뀌는 게 없다
- 이어받기: 한 박의 길이를 온음표 단위로 두고(`6/8` = 1/8, 점음표로 세면 3/8) `NOTE` 는 분당 온음표 수를 유지, `BEAT` 는 bpm 숫자를 유지
- 구간 bpm 상한 600 (`MAX_SECTION_BPM`) — 음표 길이 그대로 이어받으면 240 을 넘을 수 있다. 대화상자가 점음표로 세기를 권한다
- 악보를 다시 분석해 구간 경계가 바뀌면 시작 마디가 맞는 설정만 쓴다

## 3. 박 시각

- `ScoreFollower(…, sections)`: 마디마다 자기 구간의 세는 단위 · 템포. 예비박은 시작 마디 구간의 것. `beatTimes`(박 → 박 0 기준 초)와
  `barPositionAt(k).bpm` 을 낸다. 끝 너머 · 예비박 앞은 마지막 · 시작 템포로 잇는다(시간표가 앞뒤로 찾으므로)
- 혼자: `MetronomeClock` 이 `BarPosition.bpm` 이 있으면 그 박부터 다음 박까지 그 템포 — 샘플 단위 누적이라 `beatTimes` 와 같은 위치
- 합주: `BeatTimeline.timeOf/beatAt(…, BeatTimes)` — 기준 박의 시각은 그대로, 그 뒤는 `BeatTimes` 의 경과 시간 차이. `beatAt` 은 두 배씩 넓혀 이분 탐색.
  `EnsembleSchedule` 은 시간표와 `BeatTimes` 를 한 덩어리로 갈아 끼운다
- **연주 중 빠르기 변경**: 새 구간 템포로 `ScoreFollower` 를 다시 만들어 마디 나눔이 같으면(`sameBeatsAs`) 다음 박부터 바꾼다.
  세는 단위를 바꿔 마디 나눔이 달라지면 지금 박이 가리키는 마디가 바뀌므로 **다음 시작(이어서)부터** (안내 한 번)

## 4. 합주 (`metronome_run`)

- 새 필드 `tempo_sections`: 악보 연동일 때 둘째 구간부터의 설정 배열. 첫 구간은 기존 `bpm` · `dotted`
- 연주자는 이것과 **자기 악보**로 `forFollowing` 을 돌려 지휘자와 같은 `BeatTimes` 를 만든다 — `BeatTimes` 자체는 보내지 않는다.
  전제는 두 기기의 마디 분석이 같다는 것(지금도 마디 동기화의 전제, P05 §5 분석 공유가 이를 보장하려는 것)
- 필드가 없으면 구간을 모르는 지휘자(v0.2.4) → 곡 전체 한 템포. 빈 배열은 "구간 없는 곡"으로 구별된다
- ⚠️ **섞인 버전**: v0.2.4 연주자는 `tempo_sections` 를 무시하고 첫 구간 템포로 계속 센다 → 박자가 바뀌는 곡에서 지휘자와 어긋난다.
  합주 기기는 같은 버전으로 맞춘다(앱 시작 시 업데이트 알림이 있다)
- 지휘자는 연주 중 템포를 바꾸면 적용된 설정만 방송한다(세는 단위 변경처럼 미룬 것은 다음 시작에)

## 5. 저장 — DB v13

`app/schemas/…/13.json` 은 12.json 에 컬럼을 더해 손으로 만들었다 — **Android 빌드(kapt)가 다시 쓰므로 빌드 후 바뀐 13.json(identityHash)을 커밋할 것**.
