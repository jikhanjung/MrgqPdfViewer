# 073 — 사전 릴리스(beta) 받기 설정 · SemVer 버전 비교 (v0.5.7)

작성일: 2026-10-07
관련: [`054`](20260926_054_in_app_update.md)(앱 안 업데이트), [`P11`](20261007_P11_score_annotations_plan.md)(메모 — 이 설정으로 시험할 첫 사전 릴리스)

## 1. 왜

메모(P11) 0 · 1단계를 실기기에서 확인하려고 사전 릴리스를 내기로 했는데, 앱 안 업데이트는 `releases/latest`(302)만 봐서
사전 릴리스를 영영 못 본다. 사용자 요청(반장 세션 전달, 2026-10-07): **설정에 "사전 릴리스 받아서 써 보기"(기본 꺼짐)**.

릴리스 계획(사용자 결정): **v0.5.7 = 정식, 이 설정만**(메모는 넣지 않는다 — main 의 메모 커밋 `1d16b3f` 전 `c7280ab` 에서 `release/0.5.7` 브랜치),
**v0.6.0-beta.1 = 메모**(versionCode 47), 정식 v0.6.0 은 48. 이 설정이 든 첫 판(0.5.7)은 정식이라 앱 안 업데이트로 가고,
그 다음 사전 릴리스부터 켠 기기가 앱 안에서 받는다.

## 2. 한 일

- **목록**: 켜져 있으면 `github.com/<repo>/releases.atom`(웹 피드 — API 비인증 한도와 무관). 사전 릴리스가 들어 있는지는
  이 저장소에 사전 릴리스가 없어 neovim(`nightly` = prerelease)으로 확인. ⚠️ 피드에는 **릴리스 없는 태그도** 온다(이 저장소 v0.5.3 —
  CHANGELOG 가 빠져 릴리스 안 된 태그) → 높은 버전부터 3개까지 `releases/download/<tag>/SHA256SUMS.txt` 에 HEAD 해 302 인 첫 것을 고른다.
  피드를 못 읽거나 후보가 없으면 조용히 정식(`releases/latest`)
- **고르기**(`ReleaseInfo.candidates`): 시험 태그(`-test`, `-beta.1-test`) 빼고, 켜져 있으면 정식 · 사전 릴리스 중 가장 높은 것. 꺼지면 정식만 —
  베타를 쓰다 끄면 낮은 정식은 "새 버전"이 아니므로 내려가지 않는다
- **버전 비교**(`AppVersion`): 접미사를 문자열 → **SemVer 우선순위**(점으로 나눈 조각, 숫자는 숫자로 · 숫자 < 글자 · 조각 많은 쪽이 높음).
  이제 방어용이 아니라 실제 경로
- 설정 → 앱 정보 → 🧪 사전 릴리스(beta) 받기 (`update_include_prerelease`, 기본 꺼짐), 켤 때 "확인 전 기능이 포함될 수 있음" 안내.
  설치는 같은 길(APK 이름 · SHA-256 · 릴리스 키, debug 서명 경고 그대로)
- 테스트: `AppVersionTest` +3(우선순위 · 내려가지 않음 · 시험 태그), `ReleaseInfoTest` +2(피드 읽기 · 후보)
