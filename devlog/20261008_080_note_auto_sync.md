# 080 — 메모 자동 동기화: 목록 1분 확인 · 돌아올 때 (v0.6.2)

2026-10-08 · P11 후속 · 사용자 결정: "목록에 있을 때는 1분에 한 번 동기화 필요한지 체크하고 목록으로 돌아올 때 한 번 자동으로 동기화"

## 무엇
- **목록이 떠 있는 동안 1분마다**(`NOTES_SYNC_CHECK_MS`) `ScoreMateSync.notesNeedSync()` — 메모 목록(`GET sync/notes/`) 한 번만 받아 주고받을 것이 있는지 본다. 있으면 조용히 전체 동기화
  - 합주 중 · 대화상자 위(창 포커스 없음) · 연결 안 됨 · 이미 동기화 중이면 건너뛴다. onPause 에서 멈춘다(업데이트 확인 틱과 같게)
  - 이 경로의 동기화는 **아무것도 알리지 않는다**(`background`) — 실패가 되풀이돼도 1분마다 토스트가 뜨지 않게. 목록의 "✏️ 동기화 필요"(#079)가 남고, 🔄 를 누르면 오류가 보인다
  - 새 악보 · 곡목 변경도 그 동기화에 함께 받지만, 확인 자체는 메모만 본다(악보 쪽은 앱 시작 · 돌아올 때 · 🔄)
- **악보에서 목록으로 돌아올 때** 한 번 동기화(`syncOnReturn`, 조용히 — 바뀐 게 있을 때만 알림)
- **한 번에 하나**: `ScoreMateSync.sync()` 를 프로세스 전체 `Mutex` 로 감쌌다(목록 · 설정 "지금 동기화"가 겹치면 뒤 것이 기다린다). 목록 화면은 진행 중이면 새로 시작하지 않는다(🔄 는 "이미 진행 중")

## 판단 규칙 (`ScoreNotesSync.needsSync`)
`sync` 가 무언가 할지를 같은 규칙으로 미리 본다 — 어긋나면 1분마다 헛동기화가 돈다
- 겹마다 `base = sync ?: (0, ∅)`, `dirty = 쓸 수 있음 && ids ≠ base_ids`
- 서버 목록에 없으면 `dirty && base.revision == 0`(처음 만들 때만 — 맞춘 적이 있는데 목록에 없으면 sync 도 건드리지 않음)
- 있으면 `remote ≠ base.revision || dirty`
- 지휘자 겹은 쓸 수 있는지가 바뀌었을 때도(`conductor_writable` ≠ `sync.writable`) — 뷰어의 👤/🎼 가 따라오게

## 확인
- 단위 테스트 380개(+1: 맞춘 뒤 → 올릴 것 → 올린 뒤 → 다른 기기가 고침 → 받은 뒤) · lint 통과

## 1분 → 10분 (v0.6.2 뒤, 반장 경유 사용자 지시)
- 목록 확인 주기를 **10분 ± 30초**(`NOTES_SYNC_CHECK_MS` · `NOTES_SYNC_JITTER_MS`, 매번 새로 뽑음) — 목록을 띄워 둔 기기가 많아도 같은 순간에 몰리지 않게. 서버(sms)는 `sync/notes/` 가 메모 본문을 읽지 않게 고치는 중(앱 API 변경 없음)
- 그대로: 악보에서 돌아올 때 한 번 · 앱을 열 때 · `Mutex` 로 한 번에 하나
- 백그라운드 · 화면 꺼짐에서 멈추는가: 확인은 onResume 에서 걸고 **onPause 에서 뗀다** — 다른 앱 · 홈 · 화면 끄기는 onPause 를 부른다. TV 화면 보호기(Dream)는 액티비티를 멈추지 않을 수 있지만 창 포커스를 잃으므로 `hasWindowFocus()` 검사에서 건너뛴다(타이머만 10분마다 돌고 요청은 없다)
