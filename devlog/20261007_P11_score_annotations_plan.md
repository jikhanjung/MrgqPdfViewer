## 0. 한 줄

태블릿 · 휴대폰(터치 기기)에서 악보 위에 **펜이나 손가락으로 선을 긋고**, **고른 자리에 글자를 넣는다**.
메모는 원본 PDF 를 바꾸지 않고 **PDF 쪽 좌표(pt)로 PDF 옆 곁 파일 `.notes.json`** 에 따로 저장해(`.musicxml` 처럼 악보 파일을 따라다닌다 — 사용자 결정 2026-10-07), 클리핑 · 두 쪽 · 휴대폰 조각이 바뀌어도 악보의 같은 자리에 붙어 있는다.
각 메모는 **붙는 보표(파트)** 도 함께 적어 두어 나중에 파트보에서 그 파트 화면으로 옮길 수 있게 한다(§3.6).

## 1. 왜 · 무엇을 먼저

- 연습하며 손가락 번호 · 숨 · 활 방향 · "여기 빠르게" · 동그라미를 적는 것은 종이 악보에서 가장 흔한 동작이다. 태블릿이 생긴(#066) 지금 가장 빠진 기능
- 사용자 요청(2026-10-07): **펜/손가락 입력 전제, 선 그리기와 정한 위치에 텍스트 입력을 우선**
- 1차 범위 밖: 도형 도구(직선 · 사각 · 화살표), 음악 기호 도장(𝆑 · 숨표 · 활 기호), 형광펜 모드, 레이어, 메모 공유 — §8 이후

## 2. 사용 장면

1. 태블릿에서 악보를 연다. 화면은 지금처럼 탭 · 밀기 = 넘김
2. **펜을 대면 바로 그린다**(스타일러스는 넘김 몸짓과 겹치지 않는다 — §3.2). 손가락으로 그리려면 **✏️ 메모 모드**를 켠다(↑ 메뉴 / 길게 누르기 메뉴, 또는 화면 위 작은 ✏️ 단추)
3. 메모 모드 위에 **도구 줄**(화면 위 가장자리, 얇게): ✏️ 펜 · 🅰 글자 · 🧽 지우개 · 색(검정 · 빨강 · 파랑) · 굵기(가늘게 · 보통 · 굵게) · ↶ 되돌리기 · ↷ 다시 · ✔ 끝
4. 글자: 🅰 를 고르고 악보를 탭 → 그 자리에 입력 칸(키보드) → 입력하고 완료 → 그 자리에 글자. 이미 있는 글자를 탭하면 고치기, 끌면 옮기기, 길게 = 지우기
5. 지우개: 문지른 선(획 단위로 통째) · 글자를 지운다. 펜의 지우개 끝 · 펜 단추를 누른 채 그으면 도구와 상관없이 지우개
6. 넘기기: 메모 모드에서도 **화면 가장자리 좁은 띠(왼 · 오 8%)를 탭**하거나 페달로 넘긴다. 펜 모드(손가락 = 넘김)는 지금 그대로
7. 끝(✔ · 뒤로)을 누르면 메모 모드를 닫는다. 저장은 획마다 바로(§3.4) — "저장" 단추 없음
8. 메모 보이기/숨기기: PDF 표시 옵션 "메모 보이기"(파일별, 기본 켬). 합주 · 연주 중에도 보인다

## 3. 설계

### 3.1 좌표 — PDF 쪽 pt 에 붙인다

- 저장 좌표는 **원본 PDF 의 쪽 번호 + 그 쪽의 pt (왼 위 원점, `PdfRenderer` 크기 기준)** — 마디 박스(`ScoreMeasure`)와 같은 체계
- 화면 → pt: 지금 마디 탭(`followMeasureAt`)과 같이 **ImageView 에 실제로 걸린 행렬의 역행렬** → 표시 비트맵 px → (두 쪽이면 왼/오 판별 · 오프셋 빼기) → `fitScale` 로 나누고 위 클리핑 더하기. `ScoreOverlayGeometry` 에 `bitmapToPage(x, y)` · `pageToBitmap(page, x, y)` 를 더해 **한 공식**을 렌더러 · 마디 박스 · 메모가 함께 쓴다(드리프트 방지, #046 원칙)
- 화면 모드마다 "표시 비트맵 ↔ 쪽" 변환이 다르다:

| 화면 | 쪽 ↔ 표시 비트맵 | 메모 |
|---|---|---|
| 한 쪽 (태블릿 세로 · TV) | `PageGeometry` (fitScale · 클리핑) | 그리기 · 보기 |
| 두 쪽 (TV · 가로 태블릿) | + `TwoPageOffsets` 왼/오 | 보기 (그리기는 2단계 — 태블릿 가로) |
| 휴대폰 조각 | 폭 맞춤 한 장 렌더 + `phoneScale` · `phoneDx/Dy` 행렬 | 그리기 · 보기 — 행렬 역변환으로 같은 공식 |
| 반 쪽 넘김 (P10) | 위 · 아래가 다른 쪽 | 보기만 (반 쪽이면 메모 모드 들어갈 때 온전한 쪽으로) |
| 파트 보기 (P07) | 파트 PDF 쪽 = 원본 조각들 | 1차: **숨김 · 그리기 막음** (안내). 2단계: `PartLayout` 조각 사각형으로 원본 pt ↔ 파트 pt 를 옮겨 보이기 |

- 굵기 · 글자 크기도 **pt** 로 저장 → 확대가 달라도 악보 대비 같은 굵기

### 3.2 입력 — 펜과 손가락

- `MotionEvent.getToolType(i)`:
  - `TOOL_TYPE_STYLUS` → 메모 모드가 아니어도 **바로 펜 획**(도구 = 마지막으로 고른 펜 · 색 · 굵기). 몸짓 감지기(`touchGestures`)로 보내지 않는다
  - `TOOL_TYPE_ERASER` 또는 `BUTTON_STYLUS_PRIMARY` 눌림 → 지우개
  - `TOOL_TYPE_FINGER` → 메모 모드면 고른 도구, 아니면 지금 몸짓(넘김 · 메뉴)
- **손바닥 무시**: 펜 획이 진행 중이거나 최근 500ms 안에 펜이 닿았으면 손가락 이벤트를 버린다. 기기가 펜을 지원하면(한 번이라도 STYLUS 를 봤으면 prefs 에 기억) 메모 모드에서 손가락 그리기를 끄는 "펜으로만" 선택지(2단계)
- 메모 모드의 손가락: 한 손가락 = 그리기, **두 손가락 = 무시**(1차는 확대 없음 — §8). 가장자리 띠 탭 = 넘김
- `dispatchTouchEvent` 앞단에서 가른다: 메모 입력이면 `AnnotationInput` 이 먹고, 아니면 지금처럼 `touchGestures`
- 매끄러운 선: `getHistoricalX/Y` 로 중간 점까지 모두, 저장 전에 **Douglas–Peucker(0.3pt)** 로 줄이기, 그릴 때는 2차 베지어(점 사이 가운데점 잇기). 필압(`getPressure`)은 1차 무시(일정 굵기), 2단계에서 굵기 가중

### 3.3 그리기 — 오버레이 한 장

- `ScoreOverlayView` 와 같은 방식의 새 뷰 `ScoreNotesView`(pdfView 바로 위, 마디 박스 아래): 저장된 획 · 글자를 **쪽 pt → 표시 비트맵 px(3.1) → imageMatrix** 로 그린다. 비트맵에 굽지 않는다 — 쪽 캐시(`PageCache`)를 건드리지 않고, 메모를 켜고 끄는 데 다시 렌더할 필요 없음
- 지금 긋는 획은 화면 좌표 그대로 그리다가 손을 떼면 pt 로 바꿔 저장 목록에 넣는다(지연 0)
- 쪽 넘김 애니메이션 중엔 지금 마디 박스처럼 숨겼다가 끝나면 다시 그린다(`isAnimating`)
- 획 수천 개도 무리 없게: 쪽별로 `Path` 를 만들어 두고(행렬이 바뀔 때만 다시) `canvas.drawPath`
- 글자: `Paint.textSize = sizePt × 화면배율`, 한 줄 기본 · 줄바꿈 허용, 바탕 없음(1차). 고르는 중이면 점선 테두리

### 3.4 저장 — 곁 파일 `<PDF 이름>.notes.json` (구현 · 계획에서 바뀜)

처음엔 Room v19 표를 생각했으나 사용자가 **"메모는 악보 파일에 같이 따라다니게, musicxml 처럼"** 을 골랐다 (2026-10-07). DB 마이그레이션이 없다.

```json
{"format": 1, "pdf_sha256": "…",
 "notes": [{"id": "9f2c41d07ab35e88", "page": 0, "type": "ink", "color": "#FFE53935", "width": 1.5, "staff": 0, "points": [x, y, …]}]}
```

- 좌표 · 굵기는 원본 PDF pt(소수 한 자리). `staff` = 붙는 보표(§3.6), 없으면 생략
- **id 는 무작위 16자 문자열** — 처음엔 파일 안 증가 정수였으나 여러 기기(태블릿 · 휴대폰 · 지휘자 둘)가 서버에서 같은 문서를 합칠 때 겹친다는 ScoreMateServer 세션의 지적으로 format 1 배포 전에 바꿈
- 모르는 `type`(뒤 판의 글자 등)은 읽어서 들고 있다가 그대로 돌려 쓴다 — 옛 앱이 지우지 않게
- 쓰기는 한 줄로 세운 스레드 하나(`ScoreNotesFile.saveAsync`) — 순서가 지켜지고 뷰어를 닫아도 마저 쓴다. 다른 이름으로 쓴 뒤 바꿔 끼운다. 메모가 비면 파일을 지운다
- 획마다 바로 저장(통째로 — 메모 수가 적다). 깨진 파일은 덮어쓰지 않고 그 악보에서는 메모를 쓰지 않는다
- **새 판**: 쓴 때의 `pdf_sha256` 과 지금 PDF 가 다르면 첫 열 때 "자리가 어긋날 수 있다" 한 번 안내하고 지금 해시로 고쳐 적는다
- **따라다니기**: ScoreMate 동기화가 PDF 를 옮기면(이름 · 앙상블이 바뀜, 새 판 + 새 이름, 연결을 끊으며 로컬로) 함께 옮긴다. MusicXML · layout 은 서버 것이라 PDF 가 없어지면 지우지만 메모는 다시 받을 수 없으므로 **곡목에서 빠지거나 TV 에서 지울 때 `PDFs/.ScoreMateNotes/<score_id>.notes.json` 에 보관**했다가 그 악보를 다시 받으면 돌려 놓는다. 연결을 끊으며 파일까지 지우면 함께 지운다. 로컬 파일(웹 업로드)은 사용자가 지우면 함께 지운다(목록 · 웹 · 설정 전체 삭제)
- 합주 연주자가 받은 캐시 파일(`cacheDir/ensemble`)에 쓴 메모는 그 캐시 옆에 남는다(캐시가 비면 사라짐) — 1차는 그대로

### 3.5 화면 · 메뉴

- ↑ 메뉴(두 번 탭)와 PDF 표시 옵션(길게)에 **✏️ 메모** (터치 기기만 — TV 에는 메뉴를 숨긴다. TV 는 보기만)
- 메모 모드 동안: 도구 줄 표시, 쪽 정보 · 안내 카드 숨김, 악보 연동 · 마이크 추적은 **멈추지 않는다**(연주하며 적을 수 있게) — 다만 마이크 자동 넘김이 메모 중 쪽을 바꾸면 긋던 획은 그 쪽에 저장하고 끝낸다
- 휴대폰 조각 화면에서 메모 모드면 **세로 끌기를 막는다**(그리기와 겹침) — 가장자리 띠 탭으로만 조각 이동
- 도구 줄은 가로 한 줄, 휴대폰 가로 화면에서 높이 40dp 안

### 3.6 붙는 보표(파트) — 파트보를 위해 (사용자 요청 2026-10-07)

나중에 파트보에서도 메모를 보이려면 메모가 **어느 파트 것인지** 알아야 한다. 오선 안이면 분명하지만 보표 사이 · 위 · 아래는 애매하므로 **쓸 때 정하고, 긋는 동안 보여 준다**.

- 규칙(`NoteStaff`, 획의 위 · 아래 가운데 y, 그 쪽의 `score_staves`): 오선 안 → 그 보표(분명). 아니면 가장 가까운 보표, 둘째로 가까운 보표와 거리 차이가 둘 합의 30% 미만이면 **애매**. 가장 가까운 것도 보표 높이의 3배보다 멀면(쪽 위 제목 · 여백) **어느 파트도 아님**(전체 악보 메모, `staff` 생략)
- 표시: 긋는 동안 그 보표 띠(오선 위 · 아래 한 칸씩, 쪽 폭)를 연한 파랑으로 칠하고 이름(보표 이름 — 그 번호에 이름이 적힌 시스템이 있으면 그것, 없으면 "보표 n")을 띄운다. 애매하면 주황 + "?". 다 그은 뒤 1.2초 남긴다
- 저장: `staff` = 시스템 안 보표 순번(`partStaff` 비트와 같은 번호). 시스템은 좌표로 다시 알 수 있어 적지 않는다
- 보표 띠는 처음 그을 때 악보 분석(DB 캐시, 서버 `layout.json` 이 있으면 그것)에서 불러온다. 분석이 없는 악보(스캔 등)는 `staff` 없음
- 3단계(파트보에서 보이기)에서 `PartLayout` 조각 사각형으로 원본 pt → 파트 pt. 고쳐 붙이기(애매한 것을 손으로 다른 보표로)는 필요하면 그때

## 4. 단계

| 단계 | 내용 | 확인 |
|---|---|---|
| 0 | 좌표 공식 정리 — `ScoreOverlayGeometry` 에 쪽 ↔ 비트맵 양방향(한 쪽 · 두 쪽 · 휴대폰), 단위 테스트(왕복 오차 < 0.5px, 클리핑 · 여백 · 두 쪽 오른쪽) | JVM 테스트 |
| 1 | **선 긋기**: 곁 파일 `.notes.json`(§3.4), `ScoreNotesView`, 붙는 보표 표시(§3.6), 펜 바로 그리기 + ✏️ 메모 모드(손가락) · 도구 줄(펜 · 지우개 · 색 3 · 굵기 3 · 되돌리기/다시 · 끝), 획 단위 지우개, 가장자리 탭 넘김, 메모 보이기 옵션 | 샤오신패드(손가락 · 펜 있으면 펜), 휴대폰, TV 에서 보이기만 |
| 2 | **글자 넣기**: 🅰 도구 — 탭한 자리에 입력 칸 → 저장, 탭 = 고치기 · 끌기 = 옮기기 · 길게 = 지우기, 크기 3단(작게 · 보통 · 크게) | 같은 기기 |
| 3 | 다듬기: 필압 굵기, "펜으로만", 파트 보기에서 원본 메모 보이기(`PartLayout` 조각 사각형으로 옮김), 가로 태블릿 두 쪽에서 그리기 | |
| 4 | 나누기 · 백업(§6) | 서버와 함께 |

1 · 2단계는 각각 릴리스(태블릿 · 휴대폰). 0단계는 1단계와 같은 커밋 묶음이어도 된다.

## 6. 서버 동기화 — ScoreMateServer 076 과 함께 (2026-10-07 논의 중)

- **메모를 기기 밖으로 보내는 것은 저작권 원칙(P07 §0)과 충돌하지 않는다** — 사용자가 만든 것이고 악보 내용을 담지 않는다. 로컬 파일(웹 업로드) 메모는 보내지 않는다
- 서버 안(076): 메모는 **두 겹** — personal(본인, 그 사람의 모든 기기) + conductor(앙상블 악보당 한 벌, 멤버 모두 읽기, owner · leader 만 쓰기). 기기는 개인 메모 위에 지휘자 메모를 함께 보인다. **score id 에 묶는다**(판이 아니라). 서버는 문서를 통째로 저장하고 notes 를 해석하지 않는다
  - `GET|PUT /api/v1/scores/{id}/notes/{personal|conductor}/` — PUT `{base_revision, pdf_sha256, format, notes}`, revision 이 다르면 409 + 지금 문서 → 앱이 합쳐 다시 PUT. 빈 notes = 삭제(행은 남고 revision 오름)
  - `GET /api/v1/sync/notes/` — 곡목 안 `{score_id, layer, revision, updated_at, pdf_sha256}` 전체. sync/scores 직후 한 번, revision 이 바뀐 것만 받고 목록에서 빠진 것은 지움
- 앱 쪽 합의(제안 보냄): 문자열 id(했음) · 합치기 = **서버 ∪ 내가 더한 것 − 내가 지운 것**(곁 파일에 `"sync": {"revision", "base_ids"}` 를 두고 PUT 때 뺌) · **겹마다 곁 파일 하나**(`.notes.json` · `.conductor.notes.json`) · 동기화 상태가 있으면 메모가 비어도 파일을 지우지 않음(빈 PUT 을 보내야 하므로)
- 서버가 정한 것(2026-10-07): 지휘자 쓰기 권한은 **`sync/notes` 응답의 `"conductor_writable": [score_id …]`** — 범위 안 앙상블 악보 중 내가 owner · leader 인 것 전부(문서가 아직 없어도). sync/scores 에 두면 역할이 바뀌어도 악보 updated_at 이 오르지 않아 낡는다. id 는 문자열 최대 64자, 문서 안 중복은 400. 처음 쓰는 문서는 `base_revision` 0. 문서당 2MB(본문 2.5MB 넘어도 413). page 는 0 이상만 보고 상한은 보지 않는다(판이 바뀌어 쪽이 줄어도 옛 메모를 받음). 서버는 format · pdf_sha256 · notes 만 저장(sync 블록은 앱이 빼고 보냄). 응답 `{layer, revision, pdf_sha256, updated_at, updated_by, format, notes}`, 409 는 error 안 `current` 로 지금 문서
- **서버 1단계(메모 API) 운영 배포**(2026-10-07, ScoreMateServer 0.17.0 · migration 0007_score_notes, 서버 devlog 076 §7). **서버 2단계(웹 악보 상세에서 메모 겹쳐 보기)** 0.18.0 배포. 서버 단계 번호는 이것(076, 커밋 7731dc2) — 앱 P11 의 단계 번호와 따로 — 앱이 맞출 응답:
  - `GET|PUT /api/v1/scores/{id}/notes/{personal|conductor}/` 200 → `{layer, revision, pdf_sha256, updated_at(ISO), updated_by, format, notes}`
  - 409 → `{"error": "conflict", "message", "current": 위 모양 | null}` — null 은 서버에 문서가 없는데 base_revision > 0 → **0 으로 다시**. 두 기기가 동시에 처음 만들면 둘째가 409
  - 400 `invalid`(format ≠ 1 · id 1 ~ 64자 아님 · 문서 안 중복 · page < 0 · type 없음 · pdf_sha256 64hex 아님), 400 `no_conductor`(개인 악보에 conductor PUT, GET 은 404), 403 `forbidden`, 413 `too_large`, 404(문서 없음 · 읽을 수 없음 · layer 이름 틀림)
  - → 앱: pdf_sha256 은 **필수 아님**(없거나 비면 받고 응답은 null, 있을 때만 64hex 검사) — 그래도 새 판 안내에 쓰이니 동기화 때 계산해 채워 보낸다. 404 = 아직 문서 없음(base 0)
  - `GET /api/v1/sync/notes/` → `{"notes": [{score_id, layer, revision, updated_at, pdf_sha256}], "conductor_writable": [score_id …]}` — 내 personal 과 conductor 만, 범위 = 기기가 고른 곡목
  - 좌표 정의는 앱 것을 format 1 로 채택. 서버 `layout.json` 은 CropBox 기준 왼 위 원점이고 회전된 쪽은 비워 둔다 → 회전 없는 쪽은 같은 공간. /Rotate 확인은 웹 겹쳐 보기(서버 2단계) 때
- **메모는 불변**(반장 세션 제안 A, 채택): 내용이 바뀌면(2단계 글자 고치기 · 옮기기, 색 바꾸기 등) **옛 id 지우고 새 id**. 그러면 합치기가 집합 연산만으로 끝나고 메모별 시각 · 우선 규칙이 필요 없다. 한쪽이 지우고 다른 쪽이 고치면 고친 것(새 id)이 남는다
- **목록에서 빠짐 ≠ 메모 삭제**(제안 B, 지금 방식과 같음): sync/notes 행이 사라지는 것은 곡목 범위 밖 · 악보 삭제뿐 — 로컬 메모를 지우지 않고 동기화만 멈추고 score_id 로 보관. 삭제는 오직 `notes: []` + revision 상승으로 전달된다
- **앱 동기화 구현 때 꼭 테스트할 것**(반장 · 사용자 요청): 서버에 아직 없는 문서는 `base_revision` 0 으로 PUT, 두 기기가 동시에 처음 만들어 둘째가 409 + current 를 받으면 평소 409 와 같이 합쳐 다시 PUT — 두 경로를 단위 테스트로(가짜 서버)
- 앱 쪽 남은 것: 동기화가 뷰어의 저장 스레드와 겹치지 않게(같은 `ScoreNotesFile` 스레드로)
- 그 밖의 나중: 합주에서 지휘자 메모를 연주자에게 실시간으로(서버 conductor 겹이 있으면 대부분 해결), 메모를 구운 PDF 내보내기(인쇄용)

6. **확대** — 손글씨는 확대해서 쓰고 싶어진다. 두 손가락 확대 · 이동은 렌더 경로(1× 정수 좌표, #042)와 부딪친다 → 1차 없음, 필요하면 확대 중엔 비트맵 확대(흐려도 됨) + 놓으면 원래대로

7. **좌표 공간 정의 — 회전 · CropBox PDF**(반장 세션 제안 C): format 1 좌표 = **"표시 공간(CropBox ∩ MediaBox, /Rotate 적용 후) pt, 왼 위 원점"**(서버 문구와 같게 — `PdfRenderer` 가 주는 쪽 크기 공간). 서버는 합성 PDF 로 확인: PyMuPDF 표시 공간에서 /Rotate 90 은 (x, y) → (H − y, x), CropBox 는 원점만 옮김. Android PdfRenderer(PDFium)는 쪽 크기에 /Rotate 를 반영해 돌려주는 것으로 알지만 **확인 전**이고, 서버(PyMuPDF `page.rect`)는 회전 전 좌표라 회전 PDF 에서는 앱 메모 · `layout.json` · 웹 SVG 가 어긋날 수 있다. 앱의 마디 분석(콘텐츠 스트림 해석)도 회전을 보지 않는다. → /Rotate 90 시험 PDF 하나를 앱 · 서버가 함께 쓴다. 앱: 계측 테스트에서 PdfBox 로 /Rotate 90 · CropBox 쪽을 만들어 PdfRenderer 쪽 크기 · 메모 좌표 확인, 그 PDF 와 기대 좌표를 서버 테스트(`tests/test_score_notes_web.py`)에. 실제 악보에 회전 PDF 가 없으면 그 사실을 기록
