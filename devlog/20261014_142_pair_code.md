# 142 — 두 대로 펼쳐 보기: 첫 화면 📖 단추 · 주 기기 번호 · 보조 기기는 세 개 중 고르기

2026-10-14 · P22 후속. 사용자 요청:
"주 기기에 코드를 띄우는 게 좋을 것 같아. 짝 맞추려면 합주 버튼 옆에 페이지 모드 버튼을 하나 놓고 지휘자-연주자 연결 비슷하게
주기기-서브기기를 선택하게 하고. 주기기에 코드 띄우고 서브기기에서는 코드 세 개 중에 하나 선택하게 하고."
이어서: "페어링한 경우는 두 기기 모두 무조건 세로 모드만. 그래야 한쪽씩 보여주지."

## 왜

짝 찾기 목록은 기기 모델 이름(`Build.MODEL`)뿐이었다 — 같은 Wi-Fi 에 기다리는 기기가 여럿이거나 같은 모델이면 헷갈린다.
짝을 맺으려면 악보를 먼저 열어 보기 메뉴로 들어가야 했다.

## 바뀐 것

- **첫 화면 📖 단추**(합주 단추 옆, TV 는 숨김, `ic_pair_spread`): 흰색 = 안 함, 초록 = 짝 맺음, 초록 깜박임 = 주 기기가 기다리는 중 ·
  보조 기기가 다시 붙는 중(합주 단추와 같은 500ms). 악보 화면 보기 메뉴 "두 대로 펼쳐 보기"와 **같은 대화상자**(`pair/PairDialogs`).
- 고르기: **주 기기 · 왼쪽 / 주 기기 · 오른쪽 / 보조 기기**. 화면 이름은 "짝을 기다린 기기 · 다른 기기" → **주 기기 · 보조 기기**
  (화면 글 · 설명서 · 용어집 — main device · second device). 코드 · 프로토콜 문서의 역할 이름(`Role.PARTNER`, "짝 기기")은 그대로.
- **주 기기 번호**: 기다리기를 시작할 때 두 자리(10 ~ 99) `PairSession.code` 를 정해 크게 띄우고(닫아도 계속 기다림 · 📖 로 다시 봄 ·
  "그만 기다리기"), 찾기 알림 `pair_announce.code` 에 싣는다. 붙으면 번호 화면이 닫힌다.
- **보조 기기**: 찾은 주 기기 번호 + 미끼 번호로 **세 칸**(`PairCodeChoices`) — 처음 찾은 번호로 칸을 만들고, 나중에 찾은 번호는 미끼를
  대신해 보이는 칸이 자리를 바꾸지 않는다. 미끼를 누르면 "그 번호의 주 기기가 없어요". 15초 동안 못 찾으면 "다시 찾기".
  `code` 없는 옛 판 주 기기는 기기 이름 칸.
- **보안이 아니다**: 번호는 알림에 그대로 실리고 `hello` 에서 따지지 않는다. 저장된 짝이 다시 붙을 때(앱 재시작 · 주소 바뀜)도 번호 없이 —
  주 기기는 다시 켜질 때마다 새 번호라 따지면 다시 붙기가 깨진다. 선택 필드라 짝 판은 3 그대로.
- **세로만**: 태블릿은 원래 늘 세로, 휴대폰은 짝 동안 세로(`phoneOrientationRequest`, beta.3)였다. 보기 메뉴의 회전 줄을 짝 동안 숨겼다.

## 테스트

`PairTest` — 알림의 `code` 읽기, 번호 두 자리, 세 칸이 서로 다르고 진짜 하나, 나중 번호가 미끼를 대신 · 보이는 칸 자리 그대로 · 미끼가
없으면 칸을 늘림 · 이름 칸.

## 남은 것

- 실기기 두 대로 확인(주 기기를 첫 화면에서 켠 채 보조 기기가 붙고, 주 기기가 악보를 열면 따라 엶).
