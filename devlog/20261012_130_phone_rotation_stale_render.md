# 130 — 휴대폰 회전: 쪽 일부만 보이던 것 (늦게 끝난 렌더 · 레이아웃 전 행렬)

2026-10-12 · 사용자: "기기 회전을 따를 때 폰에서 악보를 띄운 채 가로-세로를 왔다갔다 해보면 가로일 경우는 두 페이지 모드에서 왼쪽 페이지의 위쪽 절반만 보이고 세로일 경우는 페이지의 왼쪽 아래 1/4 정도만 보이는 경우가 있어. 이게 경우에 따라 왔다갔다 하네. 기기 방향에 따라 페이지 어떻게 보여주는지 판단하는 부분을 다시 한 번 점검해줘."

## 점검
- 두 쪽 모드 판단은 맞다 — 휴대폰은 `checkAndSetTwoPageMode` 에서 늘 한 쪽, 보기 메뉴에도 두 쪽 줄이 없다. "두 쪽처럼" 보인 것은 **세로 폭(1080)으로 그린 쪽이 가로 화면(2400) 왼쪽에 1:1 로 얹힌 것**, 세로의 "왼쪽 아래 1/4"은 **가로 폭으로 그린 쪽이 세로 화면에 1:1 로**(+ 보던 칸 위치만큼 위로 밀려) 얹힌 것 — 비트맵과 행렬이 서로 다른 방향의 것
- 그렇게 되는 길 셋:
  1. **늦게 끝난 렌더**: 돌면 `rebuildForPhoneWidth` 가 새 폭으로 쪽 캐시를 만들고 `showPage` 를 다시 부르지만, 돌기 전에 시작한 캐시 미스 렌더(옛 폭)가 그 뒤에 끝나면 그 비트맵을 그대로 얹었다. 빨리 왔다갔다 할수록 잘 생긴다 — "경우에 따라"
  2. **빠른 넘김 막기에 걸림**: `showPage` 는 렌더 중이고 100ms 안이면 요청을 건너뛴다 — 돈 직후 다시 그리기가 건너뛰어지면 옛 비트맵 · 옛 행렬이 남았다
  3. **레이아웃 전 행렬**: 폭이 같아 다시 그리지 않을 때는 `post { setImageViewMatrix }` 뿐인데, 그 post 가 새 크기 레이아웃보다 먼저 돌면 옛 뷰 크기로 행렬을 잡았다
- 이 밖에 늘 보이던 늦은 렌더 덮어쓰기(캐시 미스 렌더 중 캐시에 있는 다음 쪽으로 넘기면, 앞 렌더가 끝나며 앞 쪽으로 되돌아감)도 같은 원인

## 바꾼 것
- `showSeq`: `showPage` 요청마다 번호 — 캐시 미스 렌더가 끝났을 때 더 새 요청이 있었으면 **버린다**(표시 · 진행 표시는 새 요청 몫). 캐시에서 바로 보인 요청도 최신이 되고 렌더 중 표시를 끈다
- `rebuildForPhoneWidth`: 번호를 올려 돌기 전 렌더를 버리고, 렌더 중 · 마지막 렌더 시각을 풀어 다시 그리기가 건너뛰어지지 않게, 끌던 중이면 접는다
- `pdfView` 레이아웃 크기가 바뀌면 지금 비트맵으로 행렬을 다시 잡는다(`addOnLayoutChangeListener`, 넘김 애니메이션 중 제외) — 새 렌더가 오기 전에도 옛 비트맵이 새 화면 폭에 맞게 보인다
