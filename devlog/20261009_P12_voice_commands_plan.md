## 0. 한 줄

태블릿 화면의 🎙 단추를 **누르는 동안 말하면**("57마디부터 템포 72", "첼로 파트", "다음 쪽") 기기 안에서 글자로 바꾸고(Moonshine tiny-ko, sherpa-onnx),
**규칙**으로 명령을 뽑아 지금 악보 상태에 맞는지 확인한 뒤 실행한다. 클라우드 · LLM 없음, 버튼을 뗀 뒤 실행까지 **1초 안**.

## 1. 왜 · 무엇을 먼저

- 리허설에서 지휘자가 가장 자주 하는 말이 "○○마디부터", "템포 ○○"다. 지금은 ↑ 메뉴 → 마디 골라 다시 → 커서로 마디 찾기(#053)라 여러 번 눌러야 한다
- 연주 중 손이 악기에 있는 사람(혼자 연습)에게도 같은 이득
- **정확도는 규칙이 결정한다**: 명령의 핵심은 값(마디 57 · BPM 72)이고, 어휘가 좁다. 범용 LLM · 임베딩은 "57"과 "75"를 구별해 주지 않는다 → 1차는 STT + 정규화 + 규칙만. EmbeddingGemma 2 는 파트 · 곡명 맞추기가 규칙으로 부족해질 때(§7)
- 1차 범위 밖: 항상 듣기(호출어), 합주 세션 시작 · 참여, 메모 넣기 · 지우기, TV(마이크 · 메모리 여건)

## 2. 사용 장면

1. 태블릿 지휘자가 악보를 보고 있다. 🎤 연주 듣고 넘기기가 켜져 있으면 **먼저 끈다** — 켜져 있는 동안 🎙 단추는 흐리게, 눌러도 "연주 추적을 멈춘 뒤에 말하세요"(§4.1)
2. 화면 구석의 작은 🎙 단추를 누르고 있는다 → 단추가 빨갛게. 메트로놈이 울리고 있었으면 **누르는 순간 정지**(§4.2)
3. "오십칠 마디부터, 템포 칠십이" → 단추를 뗀다
4. 화면 위에 알아들은 것을 1 ~ 2초: **"57마디 · ♩=72"** → 실행(57마디에서 예비박 → 시작)
5. 잘못 알아들었으면 다시 말한다. 못 알아들으면 "못 알아들었어요"만 — **모르면 실행하지 않는다**
6. 합주 지휘자면 🎙 정지 · 실행 결과가 지금의 합주 메시지(`metronome_run` 등)로 연주자에게 그대로 간다 — 음성 전용 메시지 없음. 🎙 를 누르면 연주자 메트로놈도 멈춘다(지휘자 ↑ 메뉴 정지와 같다)

## 3. 처리 흐름

```
🎙 누름 → 녹음(16 kHz 모노) ─ VAD 로 앞뒤 무음 자르기
🎙 뗌   → Moonshine tiny-ko (STT)
        → 정규화 (숫자 · 단위 · 악기 이름 · 자주 틀리는 말)
        → 규칙 처리기 (의도 + 값, 한 문장 여러 명령)
        → 검사 (지금 악보 · 상태에 맞는가)
        → 표시 ("57마디 · ♩=72") + 실행 (명령 층, §5)
```

### 3.1 정규화 — 규칙 정확도의 대부분이 여기서 정해진다

| 대상 | 예 | 결과 |
|---|---|---|
| 한자어 숫자 | 오십칠 · 백이십 · 칠십이에 | 57 · 120 · 72 (조사 떼기) |
| 고유어 숫자 | 쉰일곱 · 일흔둘 | 57 · 72 |
| 아라비아 숫자 | 57, 57번 | 57 |
| 마디 단위 | 마디부터 · 마디에서 · 번째 마디 · 소절 | `마디` |
| 쪽 단위 | 쪽 · 페이지 · 장 | `쪽` |
| 악기 | 첼로 · 셀로 · vc / 비올라 둘째 · 세컨 비올라 | cello / viola 2 (별칭 사전) |
| 리허설 마크 | 레터 에이 · 에이 · A | A |
| STT 오인식 | 탬포 → 템포 등 | 실녹음(§8)으로 쌓는 고침 목록 |

### 3.2 규칙 — 의도 + 값

| 발화(정규화 후) | 의도 | 값 |
|---|---|---|
| N 마디 (부터) / N 부터 | GOTO_MEASURE | measure=N |
| 템포 N / 빠르기 N / N 으로 | SET_TEMPO | bpm=N |
| N 마디 (부터) 템포 M | GOTO_MEASURE + SET_TEMPO | 두 명령, 템포 먼저 적용 |
| 처음부터 | GOTO_MEASURE | 첫 시작 가능 마디 |
| 다시 | GOTO_MEASURE | 직전 시작 마디 — `stopMetronome()` 이 `followStartMeasure` 를 지우므로 🎙 정지 전에 따로 보관 |
| 이어서 | GOTO_MEASURE | 멈춘 마디(`lastFollowPosition`, 정지가 남김) |
| 다음 쪽 · 넘겨 / 이전 쪽 · 앞 쪽 | NEXT_PAGE / PREVIOUS_PAGE | — |
| N 쪽 | GOTO_PAGE | page=N |
| 시작 · 메트로놈 | START_METRONOME | — |
| ○○ 파트 / 총보 | SELECT_PART / SHOW_FULL_SCORE | part=○○ |
| 레터 X (부터) | GOTO_REHEARSAL_MARK | mark=X — **2단계 이후**(§6) |

- **숫자만**("칠십이"): 메트로놈 대화상자가 열려 있으면 BPM, 아니면 마디. 그래도 애매하면 실행하지 않고 "마디인가요, 템포인가요?" 표시
- 규칙에 안 걸린 말은 실행하지 않는다. 오인식 기록(§8)으로 남겨 정규화 · 규칙을 늘린다

### 3.3 검사

| 의도 | 통과 조건 | 실패 시 |
|---|---|---|
| GOTO_MEASURE | 악보 분석이 있고 그 마디가 시작 가능 마디(`followMeasures`) 안 | "57마디가 없어요 (1 ~ 120)" |
| SET_TEMPO | `MetronomeClock.MIN_BPM`(20) ~ `MAX_BPM`(240). 점음표 박 곡은 지금 세는 단위의 BPM(#052) | 범위 안내 |
| GOTO_PAGE | 1 ~ 쪽 수(파트 보기면 원본 쪽 기준, `dstPageForSource`) | 범위 안내 |
| SELECT_PART | 이 악보 보표 · 파트 이름(`ScoreParts`, MusicXML 이름)에 있음 | "첼로 파트가 없어요" |
| 합주 연주자 | 마디 · 템포 · 시작 · 정지는 지휘자만(#055) — 연주자 기기에서는 쪽 · 파트만 | "지휘자가 정해요" |

## 4. 녹음 · STT

### 4.1 🎤 연주 추적과 겹치지 않는다 — 사용자 결정 2026-10-09
- **음성 명령은 연주 추적이 꺼져 있을 때만 작동한다.** 추적(`follow/MicScoreFollower`, 44.1 kHz `AudioRecord`)이 켜져 있으면 🎙 단추는 흐리게 표시하고, 누르면 "연주 추적을 멈춘 뒤에 말하세요"만 띄운다. 음성 명령이 추적을 대신 끄거나 잠시 멈추지 않는다
- 따라서 마이크를 나눠 쓰지 않는다: 🎙 를 누르는 동안만 16 kHz 모노 `AudioRecord` 를 열고, 떼면 닫는다. 리샘플 · 녹음 흐름 공유 · 추적 재위치가 필요 없다
- 음성으로 추적을 켜는 명령도 1차에는 두지 않는다(켜는 순간 마이크가 추적 몫이 되므로 🎤 메뉴로)

### 4.2 메트로놈은 🎙 를 누르는 순간 정지 — 사용자 결정 2026-10-09
- 악보 연동 · 일반 메트로놈이 울리고 있으면 🎙 를 누르는 순간 `stopMetronome()` (일시정지가 아니라 **정지**). 클릭 · 반주가 마이크에 들어가지 않는다
- 정지는 멈춘 마디를 `lastFollowPosition` 에 남긴다 → "이어서" 명령 · 다음 마디 고르기 커서가 쓴다. "다시"(직전 시작 마디)는 정지 전에 `followStartMeasure` 를 따로 보관
- 합주 지휘자면 `stopMetronome()` → `endEnsembleRun()` 으로 연주자도 멈춘다. 이어지는 "57마디부터" 가 새 실행으로 다시 알린다
- 말을 못 알아들었거나 검사에서 막혀도 메트로놈은 **멈춘 채로 둔다**(자동으로 되살리지 않는다)
- 그래서 "멈춰 · 그만" 명령은 두지 않는다 — 🎙 를 누르는 것이 곧 정지

### 4.2 STT 모델
- sherpa-onnx + **Moonshine tiny-ko(양자화, 약 69 MB)** — 1차 후보. 비교 후보: sherpa-onnx 의 다른 한국어 모델(Zipformer 계열)
- 가능하면 **핫워드 가중치**(마디 · 템포 · 쪽 · 파트 · 악기 이름 · 이 악보의 파트 이름)
- **APK 에 넣지 않는다**: 음성 명령을 처음 켤 때 받는다(`cacheDir` 아닌 `filesDir` — 지워지면 다시 받아야 하므로). 앱 안 업데이트(#054)처럼 SHA-256 검증
- VAD: sherpa-onnx Silero VAD — 푸시투토크라 꼭 필요하진 않지만 앞뒤 무음을 잘라 지연을 줄인다

## 5. 명령 층 — 음성보다 먼저

지금 페달 · 터치 · ↑ 메뉴가 `PdfViewerActivity` 의 함수를 각자 부른다. 음성(그리고 나중의 에이전트)이 같은 동작을 하려면 **명령 하나 = 함수 하나**인 층이 먼저 필요하다. 음성이 없어도 이득(동작이 한 곳에서 검사됨).

| 명령 | 지금 경로 (PdfViewerActivity) |
|---|---|
| `gotoMeasure(n)` | (🎙 가 이미 정지) 악보 분석 · 파일 설정으로 `followMeasures` 를 준비하고 `enterMeasureSelection` 없이 바로 n 마디에서 `startFollowing()` |
| `setTempo(bpm)` | 엔진 템포 + 파일별 저장(v7), 연주 중이면 `refreshFollowTempo()`(구간 곡 #057), 지휘자면 `retimeConductorRun` |
| `start()` / `stop()` | `startMetronomeWithSavedSettings()` / `stopMetronome()`(🎙 누름 · 페달 · 메뉴) |
| `nextPage()` / `prevPage()` / `gotoPage(n)` | `showPageWithAnimation` · `showPage` (두 쪽 · 반 쪽 · 휴대폰 조각 규칙 그대로) |
| `selectPart(staffMask)` / `showFullScore()` | 파트 보기 대화상자(`showPartViewDialog`)의 적용 부분 — `partStaff` 비트(v17) |

- 명령 층은 **검사(§3.3) 결과를 돌려준다**(성공 / 이유) — 음성은 그걸 화면에 표시하고, 페달 · 메뉴는 지금처럼 무시하거나 토스트
- "멈춰 있으면 마디 고르기 없이 바로 시작"은 새 동작 — 지금은 ↑ 메뉴 → 커서가 유일한 길이다

## 7. EmbeddingGemma 2 — 붙이는 조건 (요약, 자세히는 docs §6)

- 쓸 곳: Context Resolver(한국어 발화 ↔ `Violoncello` · `Vc.` · 곡명 · 리허설 마크), 의도 대체 경로(되묻기만, 바로 실행 안 함)
- 쓰지 않을 것: 오디오 인코더(STT 대체) — 값을 못 뽑고, 300M 으로 STT 보다 크고, 음악 배경 내성 미지
- 붙이는 조건: 3단계 평가에서 **파트 이름 정확도가 별칭 사전으로 목표에 못 미칠 때**
- ⚠️ float16 금지 — LiteRT GPU 델리게이트 fp16 이면 조용히 틀린 임베딩. CPU(XNNPACK) 또는 GPU fp32

## 8. 평가

- 녹음 세트: 조용한 방 · 리허설 배경음(합주 녹음을 스피커로 틀고) · 연주 직후 말하기, 각 50 ~ 100 발화. `recordings/` 처럼 기기에 남기는 도구(설정 → 🎤 녹음 기록, v0.4.1)를 재사용
- 지표와 1차 목표(조용한 방 / 배경음)

| 지표 | 목표 |
|---|---|
| **잘못 실행** (다른 명령 · 다른 값으로 실행됨) | **≤ 1% / ≤ 2%** — 가장 중요 |
| 의도 정확도 | ≥ 95% / ≥ 85% |
| 마디 번호 · BPM 정확도 | ≥ 95% / ≥ 85% |
| 악기 이름 정확도 | ≥ 90% / ≥ 80% |

- "못 알아들었어요"(실행 안 함)는 실패지만 잘못 실행보다 훨씬 낫다 — 기준을 잘못 실행 쪽에 엄하게

## 9. 열린 질문

1. **마디 번호 = 무엇?** 사람은 인쇄된 마디 번호로 말한다. 분석 번호(`ScoreMeasure.measureNumber`)가 못갖춘마디 · 반복 · 2번 괄호에서 인쇄 번호와 다를 수 있다 → 실제 악보 몇 개로 대조, 다르면 MusicXML 번호 우선
2. **단추 위치**: 태블릿 터치 몸짓(#066 — 좌우 탭 = 넘김, 가운데 두 번 탭 = 메뉴)과 겹치지 않는 자리. 페달 길게 누르기 · BLE 스위치는 선택
3. **"템포 72" 의 단위**: 구간별 빠르기 곡(#057)에서 지금 구간 템포인지 첫 구간(파일 설정) 템포인지 — 제안: 지금 구간
