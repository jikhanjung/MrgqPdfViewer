## 1. 1단계 — 설치 · 방향 · 겹침 · 페달
- 매니페스트: `android.software.leanback` **필수 아님**, `LAUNCHER` 분류 추가 → 같은 APK 가 태블릿 홈에 뜬다
- 방향: 매니페스트는 `unspecified`, **TV 가 아니면 `sensorPortrait`**(`DeviceForm.applyOrientation`, 모든 액티비티 onCreate) — TV 판별은 `UiModeManager`
- **세로 화면은 늘 한 쪽** — 저장된 두 쪽 설정은 건드리지 않는다(가로에서 열면 그대로). 표시 옵션의 두 쪽 항목은 안내만
- 세로 뷰어: 박 표시를 **가운데 위**(16:10 화면에서 A4 가 폭에 맞고 위아래가 빈다)
- 세로 파일 목록: 제목 줄 · 그 아래 "× ScoreMate ☁️"(15sp) · 그 아래 세트리스트 탭 + 🔄 동기화 (가로는 제목 옆에)
- 넘김 페달 · 키보드: PageDown · 미디어 다음 · End → 다음 쪽, PageUp · 미디어 이전 · Home → 이전 쪽 (←→ 는 원래 된다, ↑↓ 페달은 ↑ 가 메트로놈 메뉴라 맞지 않는다)
- 화면 문구 "이 TV" → 기기에 맞게 "이 태블릿" · "이 휴대폰"(`DeviceForm.noun`)

## 3. 함께 고친 것
- **합주 버전 경고 오판** (#061 부터): 지휘자는 `connect_response` 를 두 번 보낸다(연결 직후 확인 · `client_connect` 답). 첫째에 버전이 없어 연주자가
  "지휘자 v0.2.5 이하"로 잘못 알렸다 → 지휘자는 첫째에도 `app_version`, 연주자는 버전 필드가 없는 것으로는 판단하지 않는다. 실기기 확인
- **두 쪽 모드 연주자의 짝 맞춤**: 받은 쪽을 짝의 시작(1-2 · 3-4 …)으로 — 한 쪽 지휘자가 3 → 2 쪽으로 오면 1-2 를 보인다(`pairStart`). P07 4단계의 표시 모드 조합 표 참고
- **파트보에 파트 이름**: 여러 파트면 보표 앞에 `Pt. n` 대신 이름(PDF 에서 읽었거나 MusicXML) — PDF 기본 글꼴에 한글이 없어 시스템 글꼴로 그린
  작은 그림(4배 해상도)으로 넣고, 여백보다 길면 줄인다. 캐시 이름에 이름 해시(형식 9). 실기기 확인

- **지휘자는 늘 총보**: 합주 지휘자 모드에서는 파트 보기를 쓰지 않는다(저장된 선택은 두고 무시, "파트 보기"는 안내만) — P07 4단계

## 4. 쪽 캐시 줄이기
- 세로 한 쪽은 1840×2600 × 4바이트 ≈ **19MB** (TV 두 쪽 모드의 한 쪽 ≈ 3.3MB) — 예전 "6장 고정"이면 ≈ 115MB
- **지금 화면 + 다음 화면만** 캐시 · 미리 그리기(사용자 결정): 한 쪽 모드 2장, 두 쪽 모드 4장(`PageCache.SCREENS_CACHED`, 모드가 바뀌면 `resize`).
  뒤로는 그 자리에서 그린다 — 태블릿 실측 **40 ~ 55ms**(1840×2600)라 체감 없음. 예전 두 쪽 모드는 앞뒤 4쪽씩 9쪽을 그려 6장 캐시에서 서로 밀어냈다
- 태블릿 몰다우 넘긴 뒤 `dumpsys meminfo`: Java 힙 ≈ 6MB, 네이티브 ≈ 97MB, Graphics ≈ 124MB, PSS ≈ 249MB (램 8GB).
  앱 한도 256MB 는 **Java 힙** 기준이고 비트맵은 Android 8 부터 네이티브라 걸리지 않는다
- 4K 기기 대비 부채(`PageCache` 바이트 기준)도 이것으로 대부분 풀린다 — 4K 두 쪽이어도 4장
