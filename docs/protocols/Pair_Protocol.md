## 1. 무엇

태블릿 · 휴대폰 두 대를 나란히 세워 TV 두 쪽 화면 하나처럼 본다 — 한 대는 **왼쪽 자리**, 한 대는 **오른쪽 자리**.

- **펼침**(spread) = 화면에 함께 보이는 두 쪽 `(left, right)`. 쪽 번호는 **1부터**(합주 · 화면과 같게, 짝 판 3 부터).
  보통의 짝은 `(1,2)` · `(3,4)` …, 쪽 수 n 이 홀수면 마지막은 `(n, 없음)`.
  연주 중 차례 넘김에서는 `(3,2)` 처럼 왼쪽 자리에 다음 쪽이 먼저 온다(1 | 2 → 3 | 2 → 3 | 4 — `follow/RollingTurns`). 왼쪽 자리는 늘 홀수 쪽, 오른쪽은 짝수 쪽.
- **주 기기**(main) = 짝을 기다린 기기. 펼침을 **혼자 정하고** 짝 기기에 알린다. 연주(메트로놈 · 🎤 듣기 · 반주) · 합주는 주 기기에서만.
- **짝 기기**(partner) = 찾아서 붙은 기기. 받은 펼침에서 **자기 자리의 쪽만** 그리고, 넘김 입력은 주 기기로 보낸다.
- 자리는 주 기기가 정한다 — 짝 기기는 늘 그 반대.

## 2. 전송

| 무엇 | 어떻게 |
|---|---|
| 찾기 | UDP 브로드캐스트, 포트 **9094** — 주 기기가 기다리는 동안 1.5초마다 알리고, 짝 기기가 15초 듣는다 (§5). 합주 찾기(9091)와 따로 |
| 메시지 | **TCP, 포트 9093**, 한 줄(`\n`)에 UTF-8 JSON 객체 하나 — 우리 앱끼리만 통하니 WebSocket 을 쓰지 않는다. 주 기기가 듣고 짝 기기가 붙는다 |
| 악보 받기 | HTTP, 포트 **9095** — 주 기기가 짝을 기다리는 동안 **지금 악보(원본 PDF) 하나만** `GET /download/<URL 인코딩한 파일 이름>` 으로 내놓는다. 짝 기기에 같은 악보가 없을 때 (§3.2). 합주 파일 서버(8090)와 따로 |

- 주 기기는 **짝 하나**만 둔다 — 새 연결이 오면 옛 연결을 닫는다(옛 연결이 닫히는 것은 끊김으로 치지 않는다).
- 종류는 **`type`** 필드. **모르는 `type` · 깨진 줄은 버리고, 모르는 필드는 무시한다** — 나중 판이 필드를 더해도 옛 판이 죽지 않는다.
- 살아 있음: 연결된 두 쪽 모두 **2초마다 `ping`**, **7초 동안 아무 줄도 못 받으면 끊긴 것**(소켓 읽기 시간 초과).

## 3. 메시지

### 3.1 `hello` (서로, 연결 직후 한 번)

```json
{ "type": "hello", "side": "left", "version": 3, "name": "TB371FC" }
```

| 필드 | |
|---|---|
| `side` | 보내는 기기의 자리 `left` · `right` |
| `version` | **짝 판**(`PairProtocol.VERSION`, 지금 3). 다르면 받은 쪽이 짝을 풀고 "두 기기를 같은 판으로" 안내 — 짝 메시지를 바꾸면 올린다 |
| `name` | 기기 이름(Android 는 `Build.MODEL`) — 짝 기기가 주 기기를 다시 찾을 때도 쓴다 (§6) |

짝 기기는 주 기기의 `side` 의 반대를 자기 자리로 삼는다. 서로 `hello` 를 받아야 짝이 맺어진 것이다.

### 3.2 `spread` (주 기기 → 짝 기기)

```json
{ "type": "spread", "file": "Brahms Sextet.pdf", "sha256": "9f2c…", "pages": 7, "left": 3, "right": 2, "seq": 1760400000123, "clip_top": 5, "clip_bottom": 3 }
```

| 필드 | |
|---|---|
| `file` | 주 기기의 지금 악보 이름(원본 PDF 이름 — 파트 보기여도) |
| `sha256` | (선택) 원본 PDF 내용 해시(소문자 hex) — 짝 기기는 **내용으로** 같은 악보인지 본다 |
| `pages` | 주 기기가 보는 문서의 쪽 수(파트 보기면 파트 PDF 의 쪽 수) |
| `left` · `right` | 펼침의 쪽(1부터). `right` 가 없으면 오른쪽 자리는 **빈 화면** |
| `seq` | 펼침 번호 — 늘어나기만 한다(주 기기 화면을 다시 만들어도 줄지 않게 시각 기반). 짝 기기는 **이미 받은 것보다 작거나 같으면 버린다** |
| `clip_top` · `clip_bottom` | (선택) 주 기기의 위 · 아래 자르기(%) — 짝 기기는 **저장하지 않고** 같게 그리고, 짝이 끝나면 제 것으로 돌아간다. 주 기기가 자르기를 바꾸면 같은 펼침이라도 다시 보낸다 |

`left` · `right` 가 `1 ≤ x ≤ pages` 가 아니면 메시지를 버린다. 짝 기기의 처리:
1. `sha256` 이 지금 악보와 다르면 같은 내용의 악보를 찾아 연다(합주 연주자의 곡 찾기와 같은 `EnsembleFiles`). **없으면 주 기기에서 받기를 묻는다**(9095, 한 곡에 한 번). 곡 목록에 있으면 악보 화면을 연다.
2. `pages` 가 자기 쪽 수와 다르면 한 번 안내(두 기기의 파트 보기가 다름).
3. 자기 자리의 쪽으로 넘긴다 — 없으면(홀수 끝 오른쪽) 빈 화면.

주 기기가 보내는 때: 펼침이 바뀔 때마다(넘김 · 쪽 이동 · 곡 열기 · 연주 중 차례 넘김), 짝이 맺어질 때, `sync` 를 받을 때.

### 3.3 `input` (짝 기기 → 주 기기)

```json
{ "type": "input", "action": "next" }
```

| `action` | |
|---|---|
| `next` · `prev` | 짝 기기에서 넘겼다(탭 · 밀기 · 페달 · ← →) — 주 기기가 펼침 단위로(두 쪽씩) 넘기고 새 `spread` 를 보낸다. 끝 · 처음 안내 · 다음 곡도 주 기기가 |
| `sync` | 지금 펼침을 다시 보내 달라 — 짝 기기가 악보 화면 · 곡 목록으로 돌아왔을 때(떠나 있는 동안 넘겼을 수 있다) |
| `start` | 짝 기기의 ▶ — 주 기기가 **지금 펼침의 첫 마디부터** 메트로놈 악보 연동을 시작(주 기기에서 마디를 고르는 중이면 고른 마디부터) |
| `listen` | 짝 기기의 🎤 — 주 기기가 지금 펼침의 첫 마디부터 연주 듣고 넘기기(마이크도 주 기기) |
| `stop` | 짝 기기의 정지 — 주 기기가 듣기 · 메트로놈 · 마디 고르기를 멈춤 |

`start` · `listen` · `stop` 은 주 기기가 음성 명령과 같은 길로 한다. 못 하면(마디 못 읽음 · MusicXML 없음 등) 주 기기가 이유를 `notice` 로 돌려준다.

짝 기기는 넘김을 **스스로 그리지 않고** 주 기기의 `spread` 를 기다린다 — 두 기기가 따로 넘기면 어긋난다.

### 3.4 `focus` (주 기기 → 짝 기기, 짝 판 2 부터)

```json
{ "type": "focus", "measure": 57, "cursor": false, "system": 57, "system_strong": false, "waiting": null }
```

주 기기 화면의 마디 표시 — **바뀔 때만** 보낸다. 모두 PDF 악보 분석의 마디 번호(같은 PDF 면 기기마다 같다). 짝 기기는 그 마디가 자기 쪽에 있을 때만 그린다.

| 필드 | |
|---|---|
| `measure` | 노란 지금 마디(메트로놈 악보 연동 · 🎤 듣기). 없으면 지움 |
| `cursor` | true 면 노란 칠 대신 **커서 모양**(시작 마디 고르는 중 · 예비박 · 일시정지) |
| `system` | 연한 시스템 표시의 마디 — 🎤 듣기의 지금 시스템, 또는 합주 지휘자의 `follow_position` |
| `system_strong` | true 면 조금 진하게(합주 지휘자 시스템) |
| `waiting` | 🎤 듣기가 시작을 기다리는 마디 — 그 마디만 연하게 |
| `playing` | (선택) 주 기기가 하는 것 — `metronome` · `mic` · `selecting`(마디 고르는 중), 없으면 멈춤. 짝 기기의 ▶ 메뉴가 시작 · 듣기 / 정지를 고른다 |

### 3.5 `notice` (주 기기 → 짝 기기)

`{"type":"notice","text":"이 악보는 마디를 못 읽었어요"}` — 짝 기기의 `start` · `listen` 을 못 한 이유(주 기기의 화면 글 그대로). 짝 기기는 잠깐 띄운다.

### 3.6 `bye` (어느 쪽이든, 짝 판 2 부터)

`{"type":"bye"}` — 짝 풀기. 받은 쪽도 짝을 풀고 저장한 짝을 지운다(다시 붙지 않는다). 두 기기 모두 혼자 보기로.

### 3.7 `ping` (서로, 2초마다)

`{"type":"ping"}` — 내용 없음. 7초 동안 아무 줄도 없으면 끊김.

## 4. 흐름

```
주 기기 (left, 기다림)                            짝 기기 (찾기)
  UDP 9094 pair_announce 1.5초마다  ───────────▶  목록에 보임 → 고름
  TCP 9093 듣기                     ◀──────────  connect
  hello {side:left, version:2}      ◀────────▶  hello {side:right, version:2}
  spread {…, left:1, right:2, seq}  ───────────▶  2쪽 그림             (1 | 2)
                                    ◀──────────  input {next}
  spread {left:3, right:4}          ───────────▶  4쪽 그림             (3 | 4)
                                    ◀──────────  input {prev}
  spread {left:1, right:2}          ───────────▶  2쪽 그림             (1 | 2)
  — 메트로놈 연동: 2쪽에 들어서고 5초 뒤 —
  왼쪽 자리만: 3쪽 그림, spread {left:3, right:2} ─▶  그대로(2쪽)     (3 | 2)
  — 3쪽에 들어서고 5초 뒤 —
  spread {left:3, right:4}          ───────────▶  4쪽 그림             (3 | 4)
  focus {measure:12} …              ───────────▶  자기 쪽이면 노란 마디
  ping ⇄ ping (2초마다)
```

## 5. 찾기 (UDP 9094)

주 기기가 짝을 기다리는 동안(그리고 짝이 끊긴 뒤 다시) 1.5초마다, 인터페이스의 broadcast 주소들과 `255.255.255.255` 로:

```json
{ "type": "pair_announce", "name": "TB371FC", "side": "left", "port": 9093, "version": 3 }
```

짝 기기는 9094 에서 15초 듣고(같은 주소:포트는 한 번), 고른 기기의 보낸 곳 주소와 `port` 로 붙는다. 자리는 `side` 의 반대. 짝이 맺어지면 주 기기는 알리기를 멈춘다.

## 6. 끊김 · 다시 붙기 · 앱 재시작 (P22 §4)

- **끊김**(ping 시간 초과 · 소켓 닫힘): 두 기기 모두 혼자 보기(빈 자리였으면 그 펼침의 왼쪽 쪽). 주 기기는 다시 알리기 시작, 짝 기기는 **2초마다 다시 붙는다**.
  4번(약 8초) 못 붙으면 `name` 이 같은 주 기기를 UDP 로 다시 찾는다(주 기기가 다시 켜져 주소가 바뀌었을 수 있다).
- **다시 붙으면** `hello` 부터 다시 — 주 기기가 지금 펼침 · 마디 표시를 다시 보낸다.
- **짝은 기기에 저장된다**(Android `pair` prefs: 역할 · 자리 · 주 기기 이름 · 주소 · 포트). 앱이 죽었다 켜져도 주 기기는 다시 기다리고, 짝 기기는 다시 붙는다. `bye`(짝 풀기)만 지운다.
- **화면 전환**: 짝은 앱 전체에 하나라 악보 화면을 떠나도 남는다. 주 기기는 마지막으로 보낸 `spread` · `focus` 를 기억해 악보 화면이 없을 때도 다시 붙음 · `sync` 에 그것으로 답한다. 곡 목록에 있는 짝 기기는 `spread` 를 받으면 그 악보를 연다.

## 7. 합주와 함께

짝은 합주에서 **TV 두 쪽 기기 한 대** — 합주에는 주 기기만 들어간다. 합주 메시지는 바뀌지 않는다([`Ensemble_Mode_Protocol.md`](Ensemble_Mode_Protocol.md) §6).
짝 기기는 합주 연주자 모드여도 합주 메시지를 따르지 않고, 쪽 알림도 보내지 않는다.

## 8. 다른 앱이 짝이 되려면

이 문서만으로 짝 기기 · 주 기기 어느 쪽이든 만들 수 있다. 최소한:
- 짝 기기: §5 찾기 → TCP 연결 → `hello`(반대 자리 · `version` 3) → `spread` 받아 자기 자리 쪽 그리기 → 넘김은 `input` → `ping` 2초마다
- 주 기기: 9093 듣기 · §5 알리기 → `hello` → 펼침이 바뀔 때마다 `spread`(`seq` 증가) → `input` 처리 → `ping`
- 쪽 번호가 1부터인 것, `right` 가 없을 수 있는 것, `seq` 가 늘기만 하는 것을 지킨다. `focus` · `bye` 는 몰라도 짝은 된다(마디 표시 · 짝 풀기 알림만 빠짐) — 다만 `version` 은 같아야 한다.
