# 기기 사이 프로토콜

MrgqPdfViewer 기기끼리(그리고 같은 말을 하는 다른 앱 — 예: ScoreMate 앱) 주고받는 메시지. 두 가지이고 **연결 · 판이 서로 따로**다.

| | [합주](Ensemble_Mode_Protocol.md) | [짝 — 두 대로 펼쳐 보기](Pair_Protocol.md) |
|---|---|---|
| 무엇 | 지휘자 한 대 → 연주자 여럿: 쪽 · 악보 · 합주 메트로놈 · 듣기 위치 | 태블릿 · 휴대폰 두 대 = TV 두 쪽 화면 하나(왼쪽 · 오른쪽 자리) |
| 역할 | 지휘자(서버) · 연주자(클라이언트) | 주 기기(짝을 기다림 — 펼침을 정함) · 짝 기기(찾아서 붙음 — 자기 자리만 그림) |
| 찾기 | UDP **9091** `conductor_announcement` (2초마다) | UDP **9094** `pair_announce` (1.5초마다) |
| 메시지 | WebSocket(평문) **9090**, 종류는 `action` | TCP **9093** 한 줄 JSON, 종류는 `type` |
| 악보 받기 | HTTP **8090** `/download/<이름>` (지휘자의 악보들) | HTTP **9095** `/download/<이름>` (주 기기의 지금 악보 하나) |
| 판 | **합주 버전** `ensemble_version` — 지금 `0.4.0` | **짝 판** `version` — 지금 `3` |
| 판이 다르면 | 연결은 하고 양쪽에 업데이트 안내 | 짝을 맺지 않고 업데이트 안내 |
| 코드 (단일 출처) | `CollaborationProtocol` · `ensemble/` | `pair/PairProtocol` · `PairLink` · `PairDiscovery` · `PairSession` |
| 테스트 | `CollaborationProtocolTest` · `EnsembleSyncTest` | `PairTest`(루프백 TCP 포함) |

**함께 쓰기**: 짝은 합주에서 **TV 두 쪽 기기 한 대**다 — 합주에는 주 기기만 들어가고, 짝 기기는 합주 메시지를 따르지도 보내지도 않는다. 합주 메시지는 짝 때문에 바뀌지 않는다.

## 공통 규칙

두 프로토콜 모두 지킨다 — 각 문서는 이것을 다시 적지 않는다.

- **JSON 객체 하나 = 메시지 하나.** 모르는 종류 · 모르는 필드는 **무시**한다. 필드가 없거나 타입이 틀리면 안전한 기본값으로(그 필드 없이 뜻이 서지 않으면 그 메시지만 버린다) — 나중 판이 필드를 더해도 옛 판이 죽지 않게.
- **쪽 번호는 1부터.** 합주는 원본(총보) PDF 의 쪽, 짝은 주 기기가 보는 문서(파트 보기면 파트 PDF)의 쪽. 앱 안의 계산은 0부터라 메시지를 만들고 읽을 때만 옮긴다.
- **마디 번호**는 PDF 악보 분석의 마디 번호 — 같은 PDF 면 기기마다 같다.
- **같은 악보는 내용으로**: 원본 PDF 의 SHA-256(소문자 hex 64자). 파일 이름은 보조이고, 받은 이름을 경로로 그대로 쓰지 않는다.
- **원본 PDF 만 기기 밖으로.** 파트 PDF · MusicXML · 서버 분석 파일은 보내지 않는다 — 기기마다 스스로 만든다(저작권 원칙, `devlog/P07` §0).
- **시각**: 벽시계 밀리초(`timestamp` 등)와, 합주 메트로놈의 단조 시계 나노초(기기끼리 직접 비교하지 않고 잰 시계 차이로 옮긴다)를 섞지 않는다.
- **판 올리기**: 옛 기기가 모르고 무시해도 결과가 어긋나지 않는 **선택 필드 추가**는 판을 올리지 않는다. 뜻이 바뀌거나 무시하면 어긋나는 변경은 올린다(합주 버전 = 그 판의 앱 버전, 짝 판 = 1씩).

## 바꿀 때

메시지를 바꾸는 커밋은 코드 · 테스트와 함께 **해당 문서의 필드 표와 "바뀐 내력"**, 그리고 이 표의 판 칸을 고친다.
